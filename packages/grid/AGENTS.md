# grid

## Purpose

`@dineug/grid` (`private: true`) is a spreadsheet grid drawn on a Konva `Stage` through `@dineug/r-html-konva`. It holds no data: a host gives it a row count, the column definitions and a `getCell(row, col)` getter, and a draw reads only the cells in view, so a frame costs what the visible cells cost, whatever the row count. Each of the six regions (the corner, the column header, the frozen column header, the row-number header, the frozen cells and the scrolling cells) is one `k-shape` whose `sceneFunc` paints it, and an overlay layer draws the selection, the header highlights and the scrollbars. The package holds the pure models (columns, viewport and scroll mapping, selection, keys, editing, TSV, text fitting), the theme, the font metrics, that scene and the `Grid` component, which mounts the Stage under a transparent DOM scroller and feeds the models its pointer, keyboard, IME and clipboard input: the focus textarea becomes the editor over a cell, a column's own editor opens in the slot beside it, and every edit, paste or clear reaches the host as one `onCommit`. The entry exports `Grid`, its prop types, the models' and the scene's types and the two default themes. `erd-editor` lists it as a devDependency and imports nothing from it, so nothing outside this package mounts a grid yet. A change keeps the node count free of the cell count (Rules § The scene), the scene functions on the raw state (Rules § State and redraws) and every draw behind `r-html-konva`'s gate.

## Making a Change

1. **Read the files on both sides of the change** (root step 1). A change to how the scene marks, flushes or sizes the stage reads `packages/r-html-konva/AGENTS.md` (the gate, `k-shape` and `markDirty`). A change to how a Konva file compiles reads `packages/vite-plugin-r-html/AGENTS.md`.
2. **Name a new konva module in `src/imports.test.ts`.** A shipped file that constructs a new `konva/lib/*` class adds its module to `RUNTIME_MODULES`; one that names a module by type alone adds it to `TYPE_ONLY_MODULES`, and a spec-only one to `SPEC_ONLY_MODULES`. The spec fails on any konva module its lists do not name.
3. **Run the package's `test` task** (root step 3), which runs `tsc --noEmit`, then the `unit` and `browser` projects:

   ```
   pnpm exec vp run --filter @dineug/grid --fail-if-no-match test
   ```

   When the `browser` project fails to start, install Chromium with `pnpm --filter @dineug/grid exec playwright install chromium` and run the task again. A change to an export or a type runs `pnpm test` instead, since `erd-editor`'s `test` task takes this package's `dist/**/*.d.ts` as input.
4. **Run the coverage gate** (root step 4), both projects at 80% per file:

   ```
   pnpm --filter @dineug/grid --fail-if-no-match test:coverage
   ```

5. **Run root step 5**, `pnpm check` then `pnpm build`. `pnpm peer-graph` and `pnpm size` are not reached while `erd-editor` imports nothing from this package. Look at a change a person would see on the demo page (`pnpm --filter @dineug/grid dev`), which mounts `Grid` over a million rows with its selection, editing, a column's own editor, both themes and frozen columns. For a change that moves what a frame costs, run `pnpm --filter @dineug/grid bench` and report what it prints (Testing Requirements).
6. **Report as root step 7 says.**

## Rules

### Importing

- **Import konva only through `konva/lib/*`.** `src/imports.test.ts` bans the barrel anywhere, since it pulls every shape, filter and DOM binding into each consumer's build. Shipped code may name `konva/lib/Stage`, and `Context`, `Layer` and `Shape` by `import type` alone, which the spec holds in every file; a spec may add `konva/lib/Global`. Every layer, group and shape comes from a `k-*` tag, which `r-html-konva` constructs.
- **Keep konva a peer.** The host's `instanceof` checks and its gate's patch of the konva namespace assume one module, so a consumer supplies the one copy.
- **Reach a sibling by its name and a subpath its exports map opens.** `src/imports.test.ts` refuses a relative path out of `src/` and a subpath, `src/` or `dist/` included, that the sibling's `exports` do not list.
- **Draw only through the gate.** Nothing here calls `batchDraw` or `draw`: a setter marks a layer with `markDirty`, `setSize` arms a commit with `requestFlush`, and the stage is sized from `onBeforeFlush` (State and redraws).
- **Leave z-order to the host's ledger.** No file here calls `setZIndex`, a `moveTo*` method, `moveUp` or `moveDown`, since one stray call would reorder siblings behind `r-html-konva`'s ledger and fail no other spec; `src/zOrder.test.ts` scans `src/` for one (`packages/r-html-konva/AGENTS.md`, The ledger).

### State and redraws

- **Scene functions are module constants that read the raw state.** `paint.ts` holds the nine as fixed references and finds a shape's scene through a `WeakMap` keyed by its Stage (`bindScene`). The host's `setAttribute` skips a value a node already holds, so a fixed function draws again only once its layer is marked, while a function built per render would mark its layer on every commit. They read `scene.state` and `scene.frame`, never `scene.observed`, whose get trap runs on every read, and a draw makes thousands.
- **Write through the proxy, and replace a field whole.** `observed` is `observable(state, { shallow: true })`, so a template bound to a field updates when it is written, and a field changed in place updates nothing. A frozen value, such as a default theme, is held as a shallow copy (`trackable`), since r-html's proxy subscribes to no frozen object.
- **Each setter marks the layers its field draws on.** `src/scene/state.test.ts` pins this table; a new field adds a row there and here.

  | Setter | Marks |
  | --- | --- |
  | `setScroll` | the body; the overlay follows through its scroll groups' `x` / `y`, which the template writes |
  | `setSelection` | the overlay, every call, the same selection again included: trading one off-screen range for another writes nothing to a `k-rect` and still moves a header highlight |
  | `setGetters` | the body, the only layer that reads a getter |
  | `setTheme`, `setFont`, `setVersion`, `setColumns`, `setRowCount`, `setFrozenColumns`, `setRowHeight`, `setResize` | the body and the overlay |
  | `setSize` | neither; the stage draws every layer once as it resizes, and the templates it moves mark the layers they sit on |

  A setter handed what the state holds marks nothing, `setSelection` aside. A layer draw that ran out of measurements marks its own layer again from its `draw.grid` handler (Text).
- **The grid keeps no cell values.** Every draw asks the getters for every cell it paints, once each, and the measure cache keys on the text itself; a host shows a data change by raising `version` or handing new getters.
- **Size the stage after the templates, once.** `setSize` lays the regions out again, keeps the size pending and calls `requestFlush`; `GridScene`'s `onBeforeFlush` listener, which runs after r-html's drain in the same commit, resizes the stage. Konva's Stage draws every layer at once on each of its `widthChange` and `heightChange` events, so with both axes new the listener writes the width past its setter and lets the height's event alone resize. That draw reads the templates: sizing the stage before the drain would draw the overlay's clip groups and scrollbars at the old size for a frame, while the body, which reads the raw state `setSize` already laid out, draws the new range either way.
- **A layer draw settles its frame first.** Each layer's `beforeDraw.grid` handler sets the visible range, the header selections (overlay only), the fitter's font and budget and its capacity before the first shape paints. The unbinding `bindLayers` returns removes the `.grid` handlers, and `GridScene` runs it at unmount with `bindScene`'s and its `onBeforeFlush` listener's.

### The scene

- **No konva node per cell.** The body layer holds the six region shapes and nothing else. The overlay holds, per cell region, a clip group with a scroll group of five `k-rect` nodes per range (four fill boxes and the edge) and one for the active cell; a highlight `k-shape` for each of the column, frozen column and row-number headers; and four scrollbar `k-rect` nodes. The node count follows the ranges, never the rows or the cells: a cell, a label or a grid line is pixels a scene function paints.
- **Clip and scroll in two groups.** The outer `k-group` sits at the region's origin with `clipX` / `clipY` 0 and the region's size, bound to the layout alone; the inner one's `x` / `y` is minus the content point the region's corner shows, so it carries the scroll. Konva clips a group in its own space after its transform, so a clip on the scrolled group would move its window with the content, and offsetting `clipX` / `clipY` to undo that would push offsets of tens of millions of px through the canvas's float32 transform, where the edges drift. An empty region's clip is 0px wide or tall, which konva still clips to, so it draws nothing; `visible` only spares the draw a walk through its nodes.
- **Header highlights sit outside the scroll groups.** Each is a `k-shape` in its header region's clip group, in the region's own coordinates, so a half-scrolled selected column's highlight stays out of the frozen header and the corner. It repaints the cells the selection reaches opaque, in the selected tokens (`selectedHeaderBackground` with `headerText` where a range meets the row or column, `fullSelectionBackground` with `selectedHeaderText` where one spans it), since a translucent tint cannot change the label drawn under it. So a frame where only the selection changed redraws the overlay alone.
- **Cut a range's rect to the view.** `rangeBox` cuts each range to the region's view plus its 1px edge, and `fillBoxes` its fill to the view, since a canvas takes a rect's size as a float and a whole column is millions of px tall; the cut edges fall outside the clip. Every box out of view is `HIDDEN_BOX`, the same attributes whatever it stood for.
- **A range's edge runs on the grid lines around it.** A cell draws its own right and bottom lines, so a range's left and top edges take the line of the cell before, and its right and bottom edges its own last lines; where the line before is the region's edge, outside the clip, the edge takes the range's first pixels instead. A range or an active cell that starts just past the view's bottom or right side still draws its leading edge there, on the last line in view, which is the last cell's own, but not across the frozen region, whose last line is the frozen border (`rangeBox`'s `frozen`). The active cell's 2px edge takes each line and the pixel inside it.
- **The fill leaves the active cell out,** as a spreadsheet does: `fillBoxes` hands each range four boxes, above, below, left and right of the active cell, all but the first hidden for a range without it, so one cell selected draws only the active cell's edge. A range draws its fill and then its edge, so a later range tints an earlier one's edge as it tints its cells.
- **A stroked `k-rect` takes its translucency from its colour's alpha, never `opacity`, and sets `perfectDrawEnabled={false}`.** Konva draws a filled, stroked shape whose opacity is under 1 through `Stage.bufferCanvas`, which keeps the pixel ratio konva read at load. `selectionFill` is an `#rrggbbaa` token, which `src/theme.test.ts` holds translucent, so no box takes `opacity`.
- **Every node is `listening={false}`.** Konva then draws no hit canvas; a hit is the models' to find (`columnAt`, `rowAt`, `resizeEdgeAt`).
- **The draw functions take a 2D context and plain data.** `drawCells` and `drawHeaders` take a `CanvasRenderingContext2D` or `OffscreenCanvasRenderingContext2D`, the theme, the font and its metrics, the fitter and the getters, never a node or the scene state. `paint.ts` is the one glue, handing them the layer's native context, which lets `draw/*.browser.test.ts` paint them on an `OffscreenCanvas` and `src/scene/paint.test.ts` stand them in.
- **A cell paints in a fixed order.** Its background is the style hook's, else `readonlyBackground` where its column or its style is read-only, else the theme's; its text colour is the hook's, else `text`. The text sits left aligned, `CELL_PADDING` in, inside a clip of its column, so a text drawn whole or measured short stays in its column. The grid lines follow, and the frozen border runs down the frozen region's right edge.
- **`renderGridScene` exports in lower case**, as erd-editor's scene roots do: it is a call that mounts the scene on a Stage, not a component a template mounts. Its module has no default export and every config here compiles with `refresh: false`, so `vite-plugin-r-html` never makes it a refresh boundary (`packages/vite-plugin-r-html/AGENTS.md`).

### The component

- **Stack the DOM in one order.** `div.dineug-grid` (relative, `dir="ltr"`) holds a `<style>`, the Stage container (its Stage made with `listening: false`), the scroller (absolute over the whole stage, `overflow: auto`, `overscroll-behavior: contain`, `tabindex="-1"`) with its spacer, then the focus textarea and the editor slot above it. `src/Grid.browser.test.tsx` holds that order. The scroller takes every pointer and wheel over the stage; the textarea, `opacity: 0` and `pointer-events: none` while no edit is open, takes the keyboard, an IME's composition and the clipboard events. Hiding the textarea by `display` or `visibility` would blur it and end an IME composition. The scroller is out of the tab order, since Firefox and recent Chrome tab into a scroller with no focusable child and its arrows then scroll natively.
- **Keep the textarea and the slot siblings of the scroller, never its children.** The template places both from the scene state alone (`cellRect`, `placeEditor`), in the container's coordinates. Inside the scroller they would also ride its native scroll, which past `SCROLL_HEIGHT_CAP` moves at another rate than the rows, and a focused caret in one would scroll the scroller as one types. What that costs is the wheel, which the two forward by hand (below).
- **Hide the native scrollbars both ways, and clip the container.** The `<style>` holds `scrollbar-width: none` and `::-webkit-scrollbar { display: none }`, since chrome91 and Safari know only the second, and the container's `overflow: hidden` then `overflow: clip`: a box that hides its overflow is still a scroll container, which scrolls to a focused caret past its edge and slides the whole grid, and one that clips is not. It sits in the container, not in an r-html `css` sheet, which r-html adopts only into the shadow roots it registered (`defineCustomElement`'s, or one handed to `addCSSHost`), so it applies wherever a host mounts the grid.
- **Prevent the mousedown, never the pointerdown.** A cancelled pointerdown stops the mousedown after it, and focus and text selection are the mousedown's defaults, so the scroller's pointerdown stays uncancelled and its mousedown is prevented and focuses the textarea with `preventScroll`, unless a column's own editor holds the focus in the slot, which keeps it until its edit closes (`holdsFocus`). A touch pointer, any button but the main one and, on an Apple platform, Ctrl with the main button, which the system makes a right click, select, resize and drag nothing on their press (a right click's `contextmenu` aside, below). A move that finds the main button up ends a drag as a `pointercancel` does, since a native menu may take the pointerup, and so does the next press when no move came between. Touch scrolls the scroller natively, and a tap outside an open editor ends its edit as any press outside does, but nothing more: its mousedown is left to the browser, and a double tap neither fits a column nor opens an editor.
- **Forward the wheel from the siblings by hand.** A wheel's default scroll reaches only the scroll ancestors of its target, and the textarea and the slot are siblings of the scroller, so each takes a non-passive `wheel` listener, one tuple for every render so the template never rebinds it, that prevents the page's scroll and hands `wheelScroll`'s pixels to `scroller.scrollBy`: a line is a row, a page the cell area's height, and Shift turns a plain wheel sideways, as a native scroller does. The listeners stay on those two, since one on the container would sit on the scroller's own path, where a non-passive wheel listener makes every native scroll wait for the main thread. In the slot, an element between the target and the slot that can still scroll that way keeps the wheel (`scrollsWithin`), so a list a host draws there scrolls first and hands the wheel on at its end. Ctrl with a wheel is a pinch zoom and stays the browser's, and a wheel something before the grid prevented scrolls nothing, as it would scroll nothing natively, so an element in the slot that takes the wheel itself, a number spinner say, keeps it.
- **Take the right click only when the host does.** Without `onCellContextMenu` the scroller leaves `contextmenu` alone and the browser's menu opens. With it, a right click on a cell is prevented, moves the active cell there first (`clickCell`) when the cell lies outside the selection, and hands the host its row, column and client point to open its own menu at. One on a header, the corner, a scrollbar or the space past the last row or column is left to the browser either way. A menu the keyboard opens (Shift+F10 or the menu key) fires `contextmenu` on the focused textarea, a sibling the scroller never sees, so the textarea takes it the same way while no edit is open: prevented, it hands the host the active cell and the middle of where that cell shows, held inside the cell area; with an edit open the editor's own menu opens. The prop is read as the event arrives, so a host may give or drop it at any time.
- **The DOM scroller and the scene keep one scroll.** A user's scroll reads the DOM into the scene through `scrollMapping`; a keyboard move, a thumb, a track or `scrollTo` writes the scene and the DOM follows, keeping the content offset it wrote so reading it back loses no row to the scale. A new layout writes the spacer, and the scroll follows the DOM unless the rows' scale changed, when the content offset stays and the DOM moves. A scroller under `display: none` keeps no offset written to it and reads 0, so while it has no box the content offset stays through a layout and a write, and the next layout or scroll event once it shows writes it to the DOM (`unsynced`).
- **Hand each drawn prop to its setter.** `watch(props)` hands `syncProp` the name of each prop the host changed, and it calls the scene setter that draws it (`getCell` and `getCellStyle` both reach `setGetters`), so a new drawn prop adds a case there. `font` also reaches the textarea's style through the template. The callbacks are read from the props as they fire and `ariaLabel` is the template's alone, so neither needs a case.
- **Prevent what the grid acts on, never stop it.** `keyAction` reads the keys as an open editor's while an edit is open. What it answers, a move, an edit (Enter, F2), a clear (Delete, Backspace), and while editing a commit (Enter, Tab) or a cancel (Escape), is prevented and never stopped. A move goes through `moveActive`, the moved cell scrolled into view by the least distance (the far corner under Shift); a page key scrolls the rows it moved first. Every key `keyAction` answers `null` for, a printable key, an IME's and the open editor's caret keys among them, reaches the textarea and the host unprevented.
- **Report once.** A gesture's result reaches `onSelectionChange` only when it is a new object, so a press, a drag and a key report each change once; `GridHandle.select` does not echo the host's own change. `onViewportChange` reports the strict range on the next animation frame, once however many scrolls moved it and only when it changed; while a frozen column shows, `colStart` is 0. `onColumnResize` fires as a resize drag ends on a new width, or on a double click of a header edge that fits the column to the widest text of its visible rows at a new width.
- **The host keeps every width.** A resize drag draws its width through `setResize` while it lasts, held to the minimum; once it ends the column takes the width the host's `columns` hold, so a host that keeps nothing sees it go back, as a cancelled drag does without a report. The grid never writes a width of its own.
- **The handle works while the grid is mounted.** `onReady` hands it over once, after the first layout. `scrollTo` scrolls the least distance that shows the cell, clamped to the last row and column, and nowhere on a grid with no rows or columns; `select` replaces the selection; `focus` focuses the textarea with `preventScroll`. Each does nothing once the grid unmounts.
- **Match the screen's pixel ratio.** Konva reads `devicePixelRatio` once at load and makes each canvas at that ratio, so a window moved to another screen before the grid mounts would draw at the old one. The grid calls `setPixelRatio` on each layer canvas whose ratio differs at mount, and again once a `(resolution: Ndppx)` query for the ratio then stops matching; it marks each layer it changed and makes the query again at the new ratio.
- **Unmount the stage first.** `renderKonva(stage, null)` runs before `stage.destroy()`, so the scene lets go of its layers and its flush listener; then the size observer, the media query, the viewport frame, the edge scroll loop, the editing input's press listeners and the prop and layout watchers go. `src/Grid.browser.test.tsx` holds that a flush after the unmount resizes nothing and reports nothing.

### Editing

- **The focus textarea is the editor.** Idle, it sits over the active cell, held inside the cell area (`holdInside`), so an IME composes where the cell is and the caret never lies past the container's edge. An edit opens on a cell scrolled into view by the least distance first, past the header and the frozen columns, as a keyboard move scrolls (`reveal`, handed in as the editing host's), so typing, F2 or a composition on an active cell a scroll left out of view or half under the frozen columns shows its editor whole, a column's own editor and its `rect` included. It opens the same textarea over its cell, inside what the active cell's 2px edge leaves (1px in on the left and top, 2px on the right and bottom), in the grid's font and the colours the style hook gave the cell as the edit opened, its text where the cell draws its own. Enter, F2 and a double click write the value into it as the cell draws it, each tab or line break a space (`normalizeCellText`), and measure the draft against that, so an edit left as it opened commits nothing; they put the caret at its end and scroll the text to it on the `nextTick` after the template has placed the editor, since Chrome scrolls no caret a script placed into view; typing opens it with the text already typed, so the grid writes nothing then. An input that opens no edit, on a read-only cell or holding a line break, is emptied, so the idle textarea holds nothing. It follows its cell through the template: a `clip-path` trims it where the header or the frozen columns cover the cell, and once the cell of an open edit leaves the view it is `opacity: 0` and held inside the cell area, where a caret kept in it scrolls nothing. Neither `display` nor `visibility` ever hides it.
- **Never write the textarea during a composition.** A composition on an idle cell opens the edit at `compositionstart` with an empty draft and fills it through `input`. A keydown the IME holds (`isComposing` or key code 229) ends nothing, since `keyAction` answers `null`. An edit that ends mid-composition commits the text so far and leaves the textarea to `compositionend`, which empties it, as it does for a composition on a read-only cell. A double click opens nothing while a composition runs. A column's own editor cannot take over a composition in the textarea, so it opens with the composed text once the composition ends, on the cell the composition began on alone: one that ends after the active cell moved, by a press or `GridHandle.select`, drops its text and opens nothing.
- **A press outside is read first.** While an edit is open, and only then, a capture `pointerdown` listener closes it on a press outside the editor (the textarea, or the slot for a column's own editor) and off the scrollbars, before the press selects, so a press on another cell commits and then moves. It sits on the textarea's own root, and each root around it out to the document holds one more that closes the edit on a press its inner root's host never saw, since a listener outside a closed shadow root, such as `<erd-editor>`'s, finds none of that root's nodes on the press's path. A blur from the focus moving elsewhere commits the grid's own editor too. The blur is read a microtask later, since one from the window losing the focus leaves the textarea the active element and one from an unmount takes it out of the document, and neither ends the edit.
- **A column's own editor answers for itself.** A column with an `editor` takes every edit Enter, F2, a double click or typing opens on a writable cell of it, and `editor(ctx)` runs once per edit. The context holds the slot as `container`, placed over the whole cell with no inset or clip, following it and hidden inside the cell area once it leaves the view as the textarea is; the cell's `rect`, a `DOMRect` in the container's coordinates as the edit opened; the `mode`, `replace` when typing opened it and `edit` otherwise; and the `initialValue`, the typed text or the value. The host renders into the slot and focuses what it rendered, since the grid moves no focus there, and a press on the scroller, a scrollbar or another cell leaves that focus in place. Escape, in the slot unless the editor prevented it or a composition holds it (`isComposing`, or key code 229, which WebKit sends for the key that ends one), or in the textarea, reaches the `onClose` listeners as `escape`, and a press outside the slot as `outside`, which a host answers with `cancel()` and `commit(value)`; a blur ends nothing. The edit stays open until `ctx.commit` or `ctx.cancel`, with no timeout, so an editor that never answers keeps its edit open, and a context answers for its own edit alone: its calls after that edit ended do nothing. Enter and Tab in the textarea beside it do nothing, and its commit moves no selection. As it closes, the slot shrinks to nothing and the focus returns to the textarea if it was in the slot or had dropped to the body, but not while a blur in the slot is carrying it to another element: a blur reads the body as the active element while it runs, so an editor that commits from its field's blur on a Tab or a press on another field would lose that move. The slot takes `blur` in the capture phase, before the editor's own listener, and the textarea stays unfocused while that blur, still dispatching, names a `relatedTarget`. The host removes what it rendered, which the grid leaves in the slot.
- **One commit per action.** An edit commits one change with `source: 'edit'`, only when its value differs from the value it opened on (`commitEdit`), so a host's write meanwhile is not undone and a version bump never touches the draft; Enter and Tab move after it either way. A clear (`source: 'clear'`, every value `''`) and a paste (`source: 'paste'`) each commit every writable cell at once, read-only cells left out, and commit nothing when no cell is writable. A selection the host left past the last row or column by taking rows or columns away is cut there for a clear and a copy (`rangesInGrid`), as the overlay draws it, so neither writes nor reads a cell the grid no longer has, and one holding no cell clears nothing and copies nothing.
- **The clipboard is the textarea's events.** Ctrl or Cmd with C or V reaches the textarea unprevented, and the grid takes the `copy` and `paste` events the browser then fires on it. A copy writes the selection as TSV to `text/plain` and prevents the event. One whose text outgrows the longest string the engine holds (2^29 - 24 characters in V8, which a select-all over a million rows of thirty columns can pass) copies nothing and throws nothing, prevented as a refused copy is; `onReject` has no reason for it. Only the TSV's join is read that way: the getter runs outside it, so an error of the host's own getter, a `RangeError` included, reaches the host as it does from a draw. A paste reads `text/plain` alone, prevents the event so no text lands in the textarea, and writes nothing from an empty or missing one; rows past the last are kept for the host to add. While the textarea is the open editor both stay its own, but for a paste holding a tab or line break, which goes in as one line: the breaks at its end dropped, as a paste onto the cells drops them, each other one a space, inserted with `execCommand('insertText')` so the textarea's undo keeps it (`setRangeText` where an engine refuses the command). A drop of text on the open editor, which lands before any listener can place it, selects what it put in, and the grid puts that in again as one line the same way. A `beforeinput` for a line break or a paragraph, which Safari sends for a modified Return and a menu may send, is prevented, so the textarea never holds a second line. While a column's own editor is open a paste on the textarea is prevented and writes nothing, and a copy still copies the selection. The grid handles no `cut`, since the idle textarea holds nothing to cut.
- **`onReject` has two reasons.** `multi-range-copy`: the ranges share neither their rows nor their columns (`copyableRanges` answers `null`), so the copy is prevented and puts nothing on the clipboard. `paste-beyond-columns`: a paste's columns ran past the last, which the grid cannot add since the host defines the columns, so those are dropped and the rest commits first.

### Text

- **pretext is the one engine.** It decides whether a text overflows (`measureNaturalWidth`) and where it is cut (`layoutNextLine` at the content width less the ellipsis's, the trailing spaces dropped), so no second measure can disagree at the edge. A word longer than its cell breaks between graphemes.
- **Measure the string that is drawn.** `normalizeCellText` turns each tab, line feed, form feed and carriage return into one space and keeps a run a run, as a canvas draws them, and the fitter prepares it with `whiteSpace: 'pre-wrap'`, since pretext's default collapses spaces the canvas draws.
- **Skip the measure under the bound.** A text whose length times `maxAdvance` fits the content width draws unmeasured. `maxAdvance` is the widest of `W`, `가`, `漢` and `😀` in the font, and a glyph wider than all four is left to the column clip; `src/model/text.browser.test.ts` holds the bound on real faces.
- **Measure a font outside any scene function.** `measureFont` runs when the scene is created and when `setFont` runs, since it has pretext calibrate its emoji widths against a DOM span, a layout read; `src/font.browser.test.ts` holds that a cell measured after reads no DOM.
- **Keep the miss budget.** A layer draw makes at most `MISS_BUDGET` (200) pretext measurements. Past it a text that may overflow is drawn whole under its column clip and the layer marks itself dirty, so the next frame measures and cuts it; `src/model/text.test.ts` and `src/scene/GridScene.browser.test.tsx` hold both halves.
- **The cache holds one font, keyed by the text.** Its LRU holds each text's width, or its prepared segments and last cut once it overflowed, so a cell builds no key. `reserve` grows it to four times the cells a frame draws and never shrinks it, and a new font empties it.

### The models

- **Selection follows a spreadsheet.** No modifier leaves one range, Ctrl (Cmd on an Apple platform) adds one, Shift extends the last from the active cell; a header, the corner and select-all make one range each, so a million rows cost one rectangle. A gesture that changes nothing hands back the same object, so a caller tells a change by identity and reports it once.
- **A key outside `GRID_KEYS` reaches the host,** but for the A key under Ctrl or Cmd: `keyAction` also reads it as `A` under Caps Lock and as the physical `KeyA` on a layout whose letters are not Latin, so select-all works on any layout. A caller tells a key the grid consumes by `keyAction` answering anything but `null`, never by the list. `keyAction` answers `null` for a composing key (`isComposing` or key code 229), for Alt and for the other platform's modifier. The list is frozen, so a caller cannot widen what the grid swallows.
- **An edit is measured against the value it started from.** Its fields are read at the start and only input moves the draft, and `commitEdit` names a change only when the value differs from that start, so a peer's write meanwhile is not undone. A cell read-only by its column or its style takes no edit, paste or clear; a column's own editor is handed the close reason and the edit waits for it to commit or cancel.
- **TSV has no quoting.** A copy turns a tab or line break inside a value into a space; `parse` drops the empty lines at the end. Several ranges copy only over the same rows or the same columns (`copyableRanges` answers `null` otherwise). A one-cell clipboard fills every range, any other is written once from the active cell; rows past the last are kept for the host to add, and columns past the last are dropped and reported (`writableChanges`'s `beyondColumns`).
- **The scroll range is scaled once the content outgrows the cap.** `scrollMapping` maps a DOM `scrollTop` to a content offset by one ratio past `SCROLL_HEIGHT_CAP`, and snaps the last DOM pixel to the content's end, so the last row always shows; the scene's `scrollTop` is always in content pixels.

### Browser floor

- **Ship nothing the floor lacks.** `build-target.ts` sets chrome91, firefox93 and safari16.4, so shipping code calls no `Array.prototype.at` or `Object.hasOwn` (read the last element by index) and relies on no CSS a floor browser lacks without a fallback: the component pairs `scrollbar-width` with `::-webkit-scrollbar` and `overflow: clip` with `overflow: hidden` (The component). pretext segments text with `Intl.Segmenter`, which firefox93 lacks; erd-editor's memo text shares that gap.

## Testing Requirements

- **The `test` task runs both projects.** `tsc --noEmit` first, then `unit` in happy-dom and `browser` in headless Chromium, which the `browser` project needs installed (Making a Change). The `.browser.` infix alone picks the project. Neither retries a spec, so a failure is real.
- **Coverage is 80% per file on all four metrics**, over `src/**/*.{ts,tsx}` less the specs, `__test-utils__`, `src/index.dev.ts` and `src/model/types.ts`.
- **Wait with `drawn()`, never the clock.** `whenDrawn` resolves as konva books a frame, and `Layer.batchDraw` paints on the next `requestAnimationFrame`, so `drawn()` (`src/__test-utils__/scene.ts`) waits one frame after it. A draw out of measurements books another commit, so it repeats until `currentEpoch()` is the same twice in a row. Every pixel and every call count is read after it; no spec sleeps on a timer, retries, or carries `.skip` or `.only`.
- **Count the getters per draw.** `src/scene/GridScene.browser.test.tsx` resets its counters on the body layer's `beforeDraw` and holds each getter between the cells in view and (rows in view + 4) × (columns in view + 2), at any scroll and when long texts outrun the budget; `src/Grid.browser.test.tsx` holds the same bounds through the component in both cases, the cells in view read off `onViewportChange`.
- **Drive the component as its input arrives.** `src/Grid.browser.test.tsx` and `src/Grid.editing.browser.test.tsx` dispatch pointer, mouse, key and wheel events on the scroller or the textarea at points they read off the scene's nodes, and use real input (`userEvent`) where a default action is what they check: the focus a press keeps, the Tab order, typing, a click outside and the native wheel. Both size the page past the grid first (`sizePage`), since a real press or wheel lands only on what the viewport shows. The first stubs `devicePixelRatio` and `matchMedia` for the pixel ratio, and restores both.
- **Type through Chrome's own IME.** The editing spec composes over CDP, through the Vitest browser context's `cdp()` session (`Input.imeSetComposition` for the syllable being built, then `Input.insertText` to finish it, a frame waited after each), as erd-editor's `QuickSearch.browser.test.ts` does, since a synthetic `CompositionEvent` changes no `textarea.value` and so proves no first character kept. Chrome then fires the composition and input events in the order a real IME makes it fire them. It dispatches each copy and paste on the textarea as a `ClipboardEvent` carrying a `DataTransfer`, and reads what the grid wrote back from it.
- **The unit specs stand pretext and the canvas in**, since happy-dom has neither; the `.browser.` specs run the real engine and faces, comparing against what Chromium's own canvas reports, so none is gated on a platform.
- **`bench` and `bench:typecheck` are outside `pnpm test` and CI, and report only.** `pnpm --filter @dineug/grid bench` builds this package's workspace dependencies, starts `vp dev` with `E2E=1` and prints, per scenario, what a frame's work took, with no baseline file and no gate. It times konva's layer draws themselves, since the flush only books them for the next frame and the gap between frames follows the display, not the work. `pnpm --filter @dineug/grid bench:typecheck` checks the bench and its config.
