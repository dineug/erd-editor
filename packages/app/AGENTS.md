# app

## Purpose

`@dineug/erd-editor-app` (private) is the React PWA at erd-editor.io, the workspace's only React package. It wraps `<erd-editor>` in a backend-free shell: IndexedDB behind a Comlink worker, cross-tab sync over BroadcastChannel, a Workbox service worker, end-to-end-encrypted peer-to-peer collaboration. `/gdrive` edits Google Drive files; its one server part, a token relay (`src/server/auth/`), never sees a file. `/embed` shows the document its `?src=` names in a read-only `<erd-viewer>` filling the page, which other sites frame, and without one builds that URL and its iframe from a document's URL and the viewer's options. A change keeps stored documents readable and Google data out of analytics.

## Making a Change

1. Read this file; for a change reaching the element's API, `engine.js` or `peer.js`, also `packages/erd-editor/AGENTS.md` and its nested files; for `src/utils/text.ts`, `packages/replication-store-worker/AGENTS.md`.
2. Run root step 3 as `pnpm exec vp run --filter @dineug/erd-editor-app --fail-if-no-match test`.
3. Run root step 4 as `pnpm --filter @dineug/erd-editor-app --fail-if-no-match test:coverage`; add a new pure module to `coverage.include` in `vitest.config.mts`.
4. After changing `e2e/` or `playwright.config.ts`, run `pnpm --filter @dineug/erd-editor-app e2e:typecheck`, the only check of them. After changing the icon, run `google-workspace:assets`, then `google-workspace:check`, and commit the PNGs; CI runs neither.
5. Run root step 6 as `pnpm --filter @dineug/erd-editor-app e2e` for what a user sees.
6. Change with the code what describes it: `public/privacy.html` and `index.html`'s pre-paint script, which also knows an embedded viewer's URL (Rules § Policy pages and framing, § Theme and display language, § The `/embed` route).
7. In the report, leave to the owner what only production or the real Google shows (the SPA fallback's framing, the Cloudflare settings, the folder after a revoke, whether a Drive `userId` can fail to match an OIDC `sub`); deploys: root § Contracts Outside This Repo.

## Rules

### The editor element

- **The editor is a custom element**, not a React component. `viewer/editor/Editor.tsx` creates `<erd-editor>` and drives it through its methods.
- **Register it by importing `@dineug/erd-editor/erd-editor.js` for its effect** (`import '@dineug/erd-editor/erd-editor.js';`), the entry that defines `<erd-editor>`. A type-only import of `ErdEditorElement` is elided, and an unupgraded element mounts (`getSharedStore is not a function`) past `tsc` and the build. `erdEditorRegistration.test.ts` pins it beside every caller and finds no file importing the package root for its side effect.
- **The read-only viewer is `<erd-viewer>`**, made by `embed/embed-viewer/EmbedViewer.tsx` alone, which imports `@dineug/erd-editor/erd-viewer.js` for its effect the same way; `erdEditorRegistration.test.ts` pins that entry beside it too.

### Schemas and fingerprints

- **`updateAt` moves on content edits only**, peer edits and imports included, because the list sorts on it. `SchemaService` compares `toFingerprint` of `{ doc, collections, settings.databaseName, settings.ddlScripts }` on every replica `change`; view state persists `value` alone. A bump goes as `updateSchemaEntity` over its own `BroadcastChannel('@@bridge')`.
- **Nothing else bumps `updateAt`.** `updateSchemaEntity` in `services/indexeddb/modules/schema` writes only the fields given; rename, move to trash, restore, open and select pass none.
- **An unchanged `value` writes nothing**: one the service last stored or loaded, such as a scroll or a zoom on a schema that saves neither. The first change after an open stores the replica's file form, so a schema stored as `''` becomes its document on its first zoom (`schema-list.spec.ts`). An older release's value drops its derived fields and removed entities, as no edit. The baseline is the file form `setInitialValue` returns (`service.test.ts`).
- **Open from the replica's runtime value** while one is open (`SchemaService.get`, for `/` and the `/live` host), else from the stored value, which opens one. It holds removed entities, so an undo from another tab or the host restores a table whole. IndexedDB, a backup and a duplicate get the file form alone (`service.test.ts`, `host.test.ts`); a guest on an older build parses the runtime value, a version 3 document.
- **Fingerprints read the file form** (`toDocumentJson`, without derived fields, stacking order or removed entities, every collection but the dictionaries in id order and the dictionary rows in order-key order (`compareByOrder`), which every replica shares: `packages/erd-editor-schema/AGENTS.md`), so a document from another machine or build counts its first zoom as no edit. An older release's stored value is fingerprinted by its own bytes, since every compared value comes from an editor or replica that loaded it.
- **`toDriveFingerprint` leaves out only unlocked views** (`originX`, `originY`, `zoomLevel`, `canvasType` while their `LockSettingType` bit, `viewport` or `canvasType`, is off), since a Drive file is the whole document. A file from before the locks opens with every lock on, so opening it saves nothing. The two bits are copies, since importing `peer.js` would put its store in the chunk every page preloads; `documentFingerprint.test.ts` holds them to the engine's.
- **`toDriveFingerprint` sorts `doc`'s id lists**: replicas apply concurrent adds in arrival order, so two tabs that each added a table or table group would re-save each other's saves without end if the order stayed in the fingerprint. No action reorders those lists; column order lives in `columnIds`. It compares the rows of the three dictionaries as written: their order is each row's LWW order key, the same on every replica, and a sort or an insert is an edit that writes those keys (`documentFingerprint.test.ts`).

### Trash, URL and backups

- **The trash is `deletedAt` on the entity**, unindexed, so no Dexie version bump. A trashed schema leaves the list, is deselected, has its session stopped and cannot be opened.
- **Trashed schemas go for good after 30 days** (an owner decision, 2026-09-20). `isTrashExpired` counts local calendar days, so DST moves no deadline and a `deletedAt` ahead of the clock waits the full 30. Each open tab purges as its list loads, when shown again and on a new day's first `now` tick (`usePurgeExpiredTrash`, from `Sidebar`, no timer of its own), through `deleteSchemaEntityAtom` like Delete permanently, so IndexedDB, the worker's replica and the other tabs (`deleteSchemaEntity`) follow. Tabs purging one schema at once are harmless: a missing row's delete resolves, and a tab drops an id it no longer lists without a word. Past the deadline the dialog says "deletes today".
- **The selected schema lives in the URL**, as `/?schema=<id>`, so the static host needs no SPA fallback. Selecting pushes an entry, deselecting replaces it, back and forward switch schemas, and an unknown or trashed id clears it. The tab title is `<name> · ERD Editor`, else `ERD Editor`.
- **A backup is `{ format: 'erd-editor-app-backup', version: 1, exportedAt, schemas: [{ name, value, createAt, updateAt }] }`**, trash excluded, recognised by `format` whatever its name. Importing one adds copies under new ids with their times, never overwriting. A time outside 0–8.64e15 (what a `Date` holds) skips its schema; one after the import becomes the import time, so it cannot pin a schema on top.

### Import

- **Convert SQL, DBML, AML and GraphQL before storing**, since the app has no parser (an owner decision, 2026-10-04). `convertSource`, imported on demand since it brings in the whole editor, calls `setSchemaSQL` / `DBML` / `AML` / `GraphQL` with `{ placement: 'auto' }` on an `<erd-editor>` it never attaches, reads `value` once that settles and destroys the element in a `finally`; a source it throws or rejects on is an invalid file.
- **Flow places two or more related tables** on the editor's ELK worker (`packages/erd-editor/src/utils/AGENTS.md`); anything else, a failed or timed-out layout and a browser without `SharedWorker` store the grid. The element is never attached, so a slow layout's toast and its Cancel never show. Every caller (the list, the sample, `driveImport.ts`'s default `convert`) converts one source after another, and the notice comes after the last; `import-export.spec.ts` and `gdrive-files.spec.ts` check the placement.
- **The stored `value` is the file form**, so a replica opening it stores nothing anew (`import-export.spec.ts`; a `service.test.ts` case opens a source an older release converted, anchors unplaced, as no edit). The import keeps the new document's settings, so a converted source has every lock on (`lockSettings` 63) and opening and zooming it keeps the zoom at 1 (`import-export.spec.ts`).
- **An import stores everything in one `importSchemaEntities` call** and opens the last document or source, unless the selection changed meanwhile. Source extensions are an own-key `Map` lookup. `.erd` / `.vuerd` / editor `.json` are stored only in a shape `isEditorDocument` recognises (version `3.0.0` with `doc` or `settings`, or v2 with `canvas` and `table`), since the editor's parser takes any object as an empty schema. `settings` alone takes a file a later release may write without `doc` (`packages/erd-editor-schema/AGENTS.md`, Parsing).
- **Read no file over 64 MB** (`MAX_IMPORT_FILE_SIZE`), and say so in the notice: at about 600 bytes a column (the `data/` fixtures), 1,000 tables are some 14 MB and a backup of several fits, and `file.text()` of a larger stray file risks the tab.
- **Take a drop only when `dataTransfer.types` includes `Files`** (`useFileDrop.ts`), so the editor's own table and column drags pass through.
- **One file import at a time**, and the controls show it (an owner decision, 2026-10-04, as on `/gdrive`). Until its notice, `importingFilesAtom` disables Import files, spins the empty viewer's and shows a drag as Importing files… with `dropEffect` `none`; `useImportFiles` refuses files given meanwhile, without queueing. The sample keeps its own spinner and marks nothing. `/gdrive`'s empty viewer spins its Import files on `importing` too; that route takes no drops. `import-export.spec.ts` and `gdrive-files.spec.ts` hold the `convertSource` module (`support/conversion.ts`) to watch the state come and go.

### Service worker and chunks

- **A new service worker waits for the user.** `registerSW.ts` turns `waiting` into the prompt, mounted in `Root` so `/live` and the builder at `/embed` have it too; an embedded viewer renders outside `Root`, so neither this prompt nor the `outdated` one shows there. Taking it sends `SKIP_WAITING` (`messageSkipWaiting()`); only that tab reloads on `controlling`, the others show "reload to finish". Nothing reloads unasked.
- **A failed chunk load prompts a reload** (`outdated`): a deploy removes the old files, so a tab on old code, `updatedElsewhere` ones included, cannot load its lazy chunks. `watchStaleChunks` leaves Vite's `vite:preloadError` unprevented, so the import still rejects to its caller. A waiting worker found later replaces `outdated` with `available`.
- **Keep hex `[hash:8]` output names**, a contract with `sw.ts`: base64 hashes silently stop matching `CacheFirst`. They repeat under `worker`, which inherits no `build` output options.

### Action hooks and tabs

- **Action hooks settle instead of rejecting**, since components call them without waiting. Wrap each `use*` action in `useSettleReported`, which logs a failure and sends it to Sentry (a no-op outside production) once the atom rolled back exactly what it showed early. A failed update puts back exactly the fields it set, deleting those the entity lacked. Import and export failures also show in the import notice.
- **`addSchemaEntity` carries the list entry, not the document**, since the other tabs keep no values; `store.ts` drops a `value` an older build's tab sends.
- **Known limitation, not addressed: the per-tab fallbacks.** Without `SharedWorker`, each tab runs its own `SchemaService` (a dedicated `Worker`, or in-thread), whose cached replica other tabs' edits never reach: they reach IndexedDB, but the shared store passes no remote action on to its subscribers. Its backup export, duplicate and reopen then read stale data, and its next edit overwrites theirs. A fix evicts replicas or feeds them those batches.

### Collaboration

- **Collaboration stays on the main thread**, since `RTCPeerConnection` is window-only. `leader.ts` elects one tab via `navigator.locks`; `atoms/modules/sidebar/index.ts` sends each batch as `collaborativeDispatch`, by `bridge.emit` in the leader and `dispatch` elsewhere, since BroadcastChannel never echoes to the poster.
- **Join rooms only via `joinCollaborativeRoom`**, which ref-counts one trystero room per strategy and room id; after a bare `joinRoom`, one caller's `leave()` destroys another's peers.
- **Send through `sendQuietly`** (`room.ts`): a bare `action.send` rejects when a data channel closes as its peer leaves, and the unhandled rejection lands in Sentry.
- **The host sends the encrypted `participants` list** only to guests that sent a `nickname`, even empty, because trystero buffers forever a message for an action the receiver never registered. `hello` carries `{ role, nickname? }`, and the host sends its whole list, itself first (`host.ts`). The host keeps `peerId → nickname` per session. A guest takes a list only from a peer whose `hello` said host, which stops a buggy guest, not a hostile one: every peer holds the key, can claim to be host and can edit anyway. The leader tab publishes `collaborativeParticipants` over the bridge, and a newly opened tab asks with `collaborativeParticipantsRequest`.
- **Keep the secret key in the URL fragment** (`/live/#<roomId>,<secretKey>`, read in `LiveCollaborative.tsx`): it doubles as the trystero password, and a query string would leak it to server logs and referrers.

### Theme and display language

- **Theme**: `appearance` is `'dark' | 'light' | 'system'`, default `system` (an owner decision of 2026-10-11, reversing the dark default of 2026-09-19), which follows `matchMedia`. The markup stays dark for a page without script, and the pre-paint script resolves system before first paint, storage blocked included. The editor gets the preference, `system` included, and follows it through the same media query. Its theme builder's System and the command palette's Theme › System are the same `system`, so `applyPresetTheme` takes a pick from either as it comes.
- **Keep `index.html`'s pre-paint script inline**, changing it with `parseThemeState` / `resolveAppearance` and the embedded viewer's rule (`isEmbedViewerUrl`, the URL's `theme`): it applies the preference before first paint, or on an embedded viewer's URL that `theme`, else the system, reading no storage, and `theme.test.ts` runs it against all three over one table of URLs.
- **An embedded viewer follows its URL and the system alone**, from first paint: the pre-paint script reads no `@theme` there, `main.tsx` calls no `watchDisplayLanguage`, and nothing on the page mounts `Root` or applies the stored `@theme` or `@locale`, which their atoms still read as their modules load (`getOnInit`). `<html>` takes the URL's `theme`, else the system's look (`EmbedPage`), and keeps no `lang` or `dir`, which the viewer's system language would read before the browser's.
- **One display language for the app and its editors**, the editor's 25 (an owner decision of 2026-10-11, reversing the English-only shell of 2026-10-06). It never travels with a document, so a `/live` guest and its host each see their own. `@locale` in `localStorage` holds JSON, `"system"` (the default) or a language code, read on init (`getOnInit`) so the first render and the first `setLocale` name it. `system` is the browser's, since the app calls `setSystemLocale` on the builder's preview alone: the editor and `resolveDisplayLocale` both take the first of `navigator.languages` they have, else English, and follow `languagechange`.
- **Nothing is stored until a pick.** The sidebar's language menu stores its pick; the editor's picker and palette fire `changeLocale`, whose `locale` `applyPickedLocale` stores (a detail without one keeps the preference); every tab follows through the `storage` event. A stored value that is no JSON string, or an empty one, reads as `system`; any other string goes to `setLocale` as it is, since the editor ignores a code it does not know (one a newer build stored) and keeps what it shows, and the app reads such a code as `system` too.
- **Keep the language list the editor's.** `src/i18n/locales.ts` copies `LOCALES` and `resolveLocale.ts` the editor's matching, since the editor exports only their types. The codes are its `LocaleCode` and `LOADERS` is a `Record` over them, so a language the editor adds fails `tsc` here until it has a dictionary; `resolveLocale.test.ts` repeats the editor's cases.
- **English is in the entry chunk, every other language a chunk of its own** (`LOADERS`, one dynamic import each), which the service worker precaches with every `.js`. `main.tsx` renders once `watchDisplayLanguage` has the language in force, so no other language shows English first (an embedded viewer's URL, with no app text, renders at once and never calls it); a later switch keeps the language shown until the next dictionary arrives, and a load that lands after a newer pick is dropped. A failed load is reported and keeps what is shown.
- **Write the app's text through `t()`**, in `src/i18n/messages/en.ts` first, then every `<code>.ts`, which `satisfies Messages` (`tsc` refuses a missing key) and which `messages.test.ts` holds to English key for key: the same placeholders, a plural's forms exactly its language's `Intl.PluralRules` categories, the protected tokens (ERD Editor, Google, SQL, MB, the extensions and the URLs) kept, no bidi control. The editor's rules for keys, plurals, sentences and isolates (`packages/erd-editor/src/i18n/AGENTS.md` § Keys and parameters) hold here too. Google's product and button names follow Google's own localized forms (Google 드라이브, Dysk Google, Google Диск, "Sign in with Google").
- **Text kept in state is `Localized`**, `(i18n) => string`, read where it renders: the import notice, the `/gdrive` session's notices (`MESSAGES`) and `describeImportResult` / `describeDriveImport` given the reader's `I18n`. A function outside the components takes `i18n: I18n = sourceI18n` last, so its specs read English. The sample's name and a new Drive file's untitled name are written in the language shown when they are made, as data.
- **Right to left mirrors the shell, not the canvas.** `watchDisplayLanguage` sets `lang` and `dir` on `<html>`, on every page but an embedded viewer's, and `Root` wraps the routes in `radix-ui`'s `Direction.Provider`, since Radix Themes' `Theme` provides `ltr` itself; the app depends on `radix-ui` at the version Themes resolves, so they share one context. The sidebar, the sash (its chevron and tooltip side) and the rows mirror through logical CSS; what sits over the editor's canvas (the update prompt, `/gdrive`'s save status and busy note, `/live`'s participants) keeps its physical corner, since the canvas never mirrors. The editor sets its own `lang` and `dir`.
- **The policy pages and `index.html`'s `<noscript>` stay English**: they are static, scriptless and what Google's review reads.
- **Each mount sets the language before first paint.** `viewer/editor/Editor.tsx`, `gdrive/gdrive-editor/GdriveEditor.tsx` and `live-collaborative/LiveCollaborative.tsx` set `enableLocalePicker` beside `enableThemeBuilder` at creation, and call `setLocale` from a layout effect declared after the creating one, so the element has the language before first paint and again on every change. `embed/embed-viewer/EmbedViewer.tsx` sets the options its URL names, then `src`, before it attaches the viewer, so its first fetch and first paint take them; given `preview`, the builder's, it keeps one viewer for the visit, hands it every option and the browser's language before it attaches, then each change of either, and a new `src` apart.

### The auth relay

- **`src/server/auth/` uses web standard APIs only** (`Request`, `Response`, `crypto.subtle`), so the Pages Function (root `functions/api/auth/[[route]].ts`) and `vp dev` run the same handlers. `handlers.ts`, `cookie.ts` and their specs hold each route's details.
- **`start` refuses a cross-site navigation with 403 JSON** (`Sec-Fetch-Site` present and not `same-origin`), or another site could replace a running sign-in's state cookie or open ERD Editor's consent screen; the popup is opened from the app, and curl sends no such header. It seals state, PKCE verifier, attempt id and `login_hint` into `__Host-erd_oauth` (Lax, 10 minutes) and asks for `prompt=consent` and `access_type=offline`, so every browser gets its own refresh token.
- **`callback`** refuses a grant without `drive.file` (`scope_missing`) and seals `{ rt, iat }` into `__Host-erd_gdrive_rt` (Strict, 180 days). `token` renews that cookie for 180 days, never past a year from `iat` (an owner decision, 2026-09-25): the relay keeps no sessions, so a copied cookie would otherwise slide forever. A year after `iat` it answers 401 `reauth_required`. `logout` revokes the grant, signing out every device of the account.
- **Every answer is JSON** except the callback page and `start`'s 302: 401 means sign in, anything else an unavailable relay. None carries CORS headers; a POST needs its own `Origin` and `X-Requested-With: XMLHttpRequest`.
- **`readCookie` matches a name exactly**, trimming only space and tab: `String.prototype.trim` would take a name padded with a no-break space, which another host of the site may set without the `__Host-` prefix, as the relay's cookie (`cookie.test.ts`).
- **The callback page reflects nothing from the request.** Its result is a fixed enum (`access_denied`, `state_mismatch`, `invalid_grant`, `scope_missing`, `upstream`, `unknown`) in escaped `data-*` attributes of `<meta name="erd-editor-auth-callback">`. Google's `error` survives only as `access_denied`. Its one constant script, under a nonce CSP with `base-uri`, `form-action` and `frame-ancestors` at `'none'`, posts `oauth-done` on `BroadcastChannel('@dineug/erd-editor-app/gdrive-auth')` and closes the popup. The attempt comes out of the state cookie, and only when the state matches, so a callback link made elsewhere reaches no opener. The relay logs event names alone, never a token, cookie, code or callback URL.
- **What `pages.ts` reaches imports only relative paths** inside `src/server/` and names no `Buffer`, `process` or `require` (`imports.test.ts`), since workerd has neither Node's globals nor the DOM. The root `tsc` has no DOM lib, so derive a DOM type like `CryptoKey` from a value. `nodeAdapter.ts`, the one Node file, stays outside that graph.
- **The `/gdrive` client imports only `contract.ts` and `base64url.ts`** from the relay; `contract.ts` holds the callback's channel and marker, the scopes, `hasDriveFileScope`, `isLoginHint` and Google's revoke URL. Both import nothing and only declare, so the client chunk carries no server code (`imports.test.ts` holds every non-test source outside `src/server/` to those two). A constant both sides need goes into `contract.ts`.
- **Bind fetch where the relay is assembled** (`fetch: (input, init) => fetch(input, init)` in `pages.ts` and `nodeAdapter.ts`): workerd and Chrome throw Illegal invocation on a fetch called through another object, which the client would read as an unavailable relay.
- **Vite's `cors` middleware runs ahead of every plugin's**, so the dev adapter drops the headers it set, and an `OPTIONS` preflight gets Vite's 204 where Pages answers 405.

### Relay variables

- **The relay reads `GOOGLE_CLIENT_SECRET`, `COOKIE_KEY` and `VITE_GOOGLE_CLIENT_ID`** (the key 32 bytes as base64, `openssl rand -base64 32`); the `build` task passes the client id alone to the bundle too (`cache.env`). Without all three it answers 503 JSON, except `token` without a cookie (401) and `logout` (200, clearing a stale cookie). A new `COOKIE_KEY` signs everyone out once.

The production client lists `https://erd-editor.io` alone: its id is public, and a localhost origin would let any page served on 5175 get Drive tokens under ERD Editor's name.

### Google sign-in on `/gdrive`

- **Judge the relay by its JSON contract alone** (`authMode.ts`): 200 with `access_token` and `expires_in` is a token and 401 with `error` means sign in. Anything else (HTML, a 429 or 1027 page, a network error, ten silent seconds) marks it unavailable in `localStorage` (`@dineug/erd-editor-app/gdrive-relay-unavailable-until`) until UTC midnight, when Workers' free quota resets. Offline decides nothing. Meanwhile no tab calls `/api/auth/*`, so the refresh cookie survives the GIS fallback until a sign-out, which asks the relay too, so a shared computer keeps no cookie. Sign in, Reconnect Google, a tab shown again and a click in an expired fallback read the flag again, so a tab follows another into the fallback and tries the relay first past midnight.
- **`signOut()` resolves `{ confirmed, revoked }`** for the screen: `confirmed` once the relay cleared the cookie, `revoked` once the grant ended, by the relay's logout (`{ ok: true, revoked }`) or by this tab (GIS `revoke` in the fallback, else a form POST to `oauth2.googleapis.com/revoke` for a live token). Revoked by nobody, the tab still signs out, saying other devices may stay signed in until access is removed at myaccount.google.com/permissions. Unconfirmed, `@dineug/erd-editor-app/gdrive-relay-logout-pending` in `localStorage` sends the logout ahead of the next token request; while it fails no token is asked for, a sign-in whose callback reported success clears it, and relay logouts run one after another.
- **A sign-out ends sign-ins open in every tab** (`signed-out` with `fromSignOut`, kept as `bySignOut` until a token comes): the popup is abandoned and a token client request settles as cancelled; a success still arriving within the attempt's five minutes logs out at the relay again. A 401's `signed-out` ends no sign-in.
- **The access token stays in memory** and on one channel (`tokenManager.ts`), `BroadcastChannel('@dineug/erd-editor-app/gdrive-token')`, renewed under the lock `@dineug/erd-editor-app/gdrive-token-refresh`. A tab asks the others and waits 200 ms, inside the lock too, since messages and lock grants have no order, so tabs make one relay call. A sign-out wins over answers asked before it. `/token`'s `scope`, the token client's and Drive's 403 `insufficientPermissions` each mean `scope-missing`; a grant that names no scope says nothing. A 401 for a token already renewed gets the new one, never a second renewal, and a tab's own sign-in wins over a renewal asked before it, so an account switch cannot stop its own tab as `account-changed`. The module and its spec hold the timing, revoke paths and `account-changed`.
- **The fallback is the GIS token client alone** (`gis.ts`, loaded only on entering it, blocked after ten seconds), for sign-in, Try again and Reconnect Google. Past the recorded midnight Reconnect Google opens no popup: one `POST /api/auth/token` decides. It renews on the next click or keyup capture outside anything editable, checked on `composedPath()`; `<erd-editor>` counts whole, since its closed shadow root hides its inputs (happy-dom shows them, Chrome does not). A renewal nobody asked for that fails waits for Reconnect Google or any new token.
- **Mark every sign-in and sign-out control** with `AUTH_CONTROL_ATTRIBUTE` (`data-gdrive-auth-control`): Sign in, Continue with Google, Try again, Reconnect Google, Switch account, Sign out, the leave dialog's Sign out anyway (never its Leave anyway), Cancel. The window's capture listener runs before a button's handler, so an unmarked control's click would first open a renewal; one that then asks for a sign-in takes that renewal over, so its failure still shows.
- **The sign-in popup never trusts the DOM** for its result (`oauthPopup.ts`): opened inside the click with a fresh attempt id, it takes only that attempt's `oauth-done`, else one `POST /api/auth/token` decides once it closes, shows a same-origin page without the callback's marker (a missing `_routes.json`'s SPA, a 1027 page), times out or is cancelled. A pending logout goes first, after up to `CALLBACK_GRACE_MS` for the callback. `oauthPopup.ts` and its spec hold the answer mapping, the five-minute listen after a cancel (COOP can close it early) and how a crossing `oauth-done` wins.

### Drive calls and the ERD Editor folder

- **Every Drive call names its `fields`** (`driveClient.ts`, `FILE_FIELDS` and friends): without them Drive answers `kind,id,name,mimeType`, and a save without `modifiedTime` makes every later save a conflict. A content PATCH is `uploadType=media` with the file's own mimeType as `Content-Type`, which Drive would otherwise take as the new one; a create is one multipart POST, always with a parent (`NewDriveFile.parentId` is a string), and the ERD Editor folder's is a JSON POST to `/drive/v3/files`.
- **Retry no POST**, which could create a file twice. `withRetry` reruns a whole cycle after a network error, 5xx, 429 or 403 rate limit, three times at 1, 2 and 4 seconds plus jitter; the client retries only one 401, with a renewed token. Errors carry the kind and Google's reason, never a file id or name.
- **Bind fetch and `window.open`** where the client is assembled, as for the relay: `components/gdrive/useGdriveSession.ts`, which also turns the route's `state` and `file` query into the session's location and takes `navigate` back as `setSearchParams`.
- **New and imported files go in one folder**, ERD Editor, never loose in My Drive (`appFolder.ts`; an owner decision, 2026-09-25, with no Picker). The Marketplace's Drive app rule asks for it: "creates and reuses an app-specific folder … doesn't dump files into the user's My Drive folder". The sidebar's New file, every Import, Drive's New without a `folderId` and the create dialog's Create in the ERD Editor folder use it; Drive's New with a `folderId` creates in that folder. It is found by its marker `appProperties: { erdEditorFolder: '1' }` alone.
- **Pick only a folder the account owns** (`ownedByMe`): another person's shared ERD Editor folder carries the marker too, and its files take on its sharing. Every use lists again under the lock `@dineug/erd-editor-app/gdrive-folder/<sub>` and takes the oldest open one (`pickAppFolder`). Ids stay in memory, never in `localStorage`, which would outlive a sign-out; `appFolder.ts` and its spec hold the rest of the lookup.
- **The folder lasts only while the grant does**: a sign-out or a removed access revokes `drive.file` access to it, so the next lookup makes another, as the policy says. No fake's revoke removes access, so check it by hand on the real Drive (sign out, sign in, New file); if the folder is still found, this entry, `appFolder.ts`'s comments and the policy change.

### Drive file sync

- **One tab saves a Drive file**: the holder of its lock (`fileLeader.ts`), named like its channel `@dineug/erd-editor-app/gdrive-file/<sub>/<fileId>` (`fileChannelName` is `fileLockName`), so other accounts' tabs never meet. Every load turns away a trashed file, a Google Doc or one over 64 MB. The first tab turns away anything `isEditorDocument` refuses, which lets the lock go and never saves. A follower never reads Drive while a tab holds the lock. Without Web Locks every tab leads, and two PATCHes can overlap (Firefox 93–95; not addressed).
- **Every message carries its sender's epoch**, new for each load from Drive: another epoch's `actions`, `saving` and `saved` are dropped, and only `snapshot` and `reloaded` set it. The four presence trackers (`editor.sharedMouseTracker`, `sharedFocusTracker`, `sharedSelectionTracker`, `sharedDragSelectTracker`) stay off the channel, since one person's tabs are no peers.
- **A `snapshot` carries both forms**: `value`, the file form a new tab saves, and `runtimeValue`, removed entities included, which its editor starts from; a PATCH, a download and every fingerprint read the file form. A leader on an older build sends `value` alone, and a load from Drive or a `reloaded` starts from the file. A detached editor leaves its document in both forms, so one attached again in the same load starts from its runtime value, and edits an account screen took it from still count, download and get saved.
- **The Drive list's news travels on `@dineug/erd-editor-app/gdrive-files/<sub>`** (a rename, a new file, a save, a folder no list shows yet); `conflict` and `unconfirmed` travel as the leader's `status`. The session writes the snapshot's base `modifiedTime` into the list, never moving an entry back, so the open file climbs the sidebar and its "Edited …" follows, as on `/`; the leader's session posts it as `saved` for the account's other tabs.
- **Every tab runs the save debounce**, two seconds after the last change and ten at most (`saveQueue.ts`). Edits are told by `toDriveFingerprint`, so a zoom or a scroll never saves, locked or not, and moving a lock (an unlock and a lock again) does. `conflict`, `unconfirmed`, `deleted`, `readonly`, `account-changed` and `scope-missing` stop saving until the person acts; a token the fallback let expire pauses it until the token manager has one again, which also resumes `scope-missing`. A leader that goes hidden saves at once, and a `saved` older than the base never moves it back.
- **Nothing overwrites a change made outside the tabs.** A moved `modifiedTime` stops saving as `conflict`, or `unconfirmed` while an attempt is unaccounted for. Check Drive (`checkUnconfirmed`, an owner decision, 2026-09-25) compares the file's Drive fingerprint with the attempt's: the same moves the base and resumes saving; anything else is a conflict.
- **A follower warns on `beforeunload`** (`followerHasUnsavedChanges`) for a change in the last 500 ms, an edit of its own no leader `status` has followed, or a leader whose last status is `saving`, `failed`, `paused`, `waiting-leader`, `conflict` or `unconfirmed`; the leader compares fingerprints. The window starts at the press (the adapter's `onInput`, a pointer or key released in the element), since `change` comes 200 ms after the edit. Its own edit is a `subscribeLocal` batch with an action outside `NON_EDIT_ACTIONS`, the followed view (`SharedFollowingActionTypes`) and the LWW handshake, or with a name view switch whose `payload.shared` is true: one made while its lock was off, which every tab takes and the file saves, where any other shows on its own tab alone; its `change` event, which another tab's batch and a zoom of an unlocked view fire too, counts nothing and asks for no save, and nothing counts on a file it may not edit.
- **`fileLeader.ts`, `saveQueue.ts`, `fileChannel.ts`, `documentController.ts`** and their specs hold the rest: hellos, takeovers and the steal fence, attach order, retries, Reload from Drive, renames, `flush()`.

- **`/gdrive` is its own lazy route**, linking nothing of `/`, nor `/` to it. `GdriveRoute` answers a frame (`isFramed`), a build without a client id and an unlisted origin (a `pages.dev` preview) before any session. ### The `/embed` route

- **`/embed` is a top-level route, apart from `/`.** `EmbedShell` renders a bare `<Outlet />` on an embedded viewer's URL and `Root` otherwise, and the lazy index child `EmbedRoute` picks the page by the same rule, `isEmbedViewerUrl`: `/embed` as the router matches it (any case, percent-encoded, trailing slashes) with a non-empty first `src`. The defaults are copies of the viewer's (`indigo` and `slate`, not the app's `jade` and `olive`).

- **`toGithubRawUrl` applies where `EmbedViewer` sets `src` and on the builder's line naming what its preview fetches, and nowhere else.** A GitHub `blob/` or `raw/` file page or a gist page goes to its raw host, which answers another site's fetch where github.com's redirects carry no CORS header, for public repositories and gists but not private repositories. - **The link reads `erd-editor.io`**, untranslated, and opens the site in a new tab (`rel="noopener"`) with no referrer (`referrerPolicy="no-referrer"`), so a click hands the site no document URL for the analytics and Sentry scrubs to catch. It takes the viewer's look through Radix's scale on its own `light-theme` or `dark-theme` class, never the app's `Theme`.

The document URL applies on Enter or blur, trimmed, so typing fetches nothing, and once one is applied the line under the field names what the preview fetches; the options and the height apply at once. The preview is `EmbedFrame` in a box as high as the iframe, with one `<erd-viewer>` for the visit: every option goes to it, each default as the viewer's own (`applyPreviewOptions`), so a pick put back undoes itself, with the browser's language as its system one, since the page's `lang` is the app's; a URL cleared sets `src`, then `value`, empty, since a `src` emptied alone keeps the document drawn.
- **The builder writes what a page pastes**: `toEmbedUrl` from `location.origin`, and `toIframeSnippet`'s line exactly, `<iframe src="<URL>" width="100%" height="<h>" style="border: 0" loading="lazy" title="ERD Editor"></iframe>`, with no `sandbox` or `allow` and 480 for a height that is no positive whole number. Each has a copy button, disabled until a URL is applied, that reads Copied for two seconds while its value is still the one copied, which a visually hidden `role="status"` beside it says too, for a screen reader; the code's is the page's one primary.
- **Nothing in the app links to `/embed`** (an owner decision, 2026-10-27); only the READMEs and the docs point people at it.

### Analytics and Sentry

- **Limited Use keeps Google data out of analytics.** The gtag snippet adds its script only off `/gdrive` and `/api/auth`. A deploy without `_routes.json` answers `/api/auth` with the app, in the sign-in popup with `login_hint` and `code` in its URL.
- **An `/embed` page gives Google Analytics its path alone.** On `/embed` and the paths below it, a segment match so `/embedded` is not one, the snippet's `config` sets `page_location` to `origin + '/embed'`, so the page view `config` sends names the path alone, not the document `?src=` names; the title stays `ERD Editor`. A page whose referrer is such a page on the same origin gets that address as `page_referrer` too, since the app sets no page-wide referrer policy and the browser's default sends its own origin the full URL, query included, which gtag.js would send from `document.referrer`. `gtagSnippet.test.ts` runs the script on stubs, so what gtag.js sends once loaded, history-based page views included, shows only in the browser's network panel.
- **Sentry traces no request to Google or `/api/auth/`** (`sentryScrub.ts`), maps `/files/<id>` to `/files/[id]`, and drops the query and fragment of every Drive, `/gdrive`, `/api/auth`, `/live` and `/embed` URL: the room and key of a `/live` invite, and the document an `/embed` page names in `?src=`. It scrubs them in the request and its Referer, the transaction, span and breadcrumb data, and the `filename` and `abs_path` of exception frames, where a global error with no file of its own names the page. Tags carry `gdrive.mode` and `gdrive.saveState`, never an id. These checks and gtag's match a path in any case and percent-encoding, as the router does, and like it decode the path alone, so a broken escape in the query hides nothing.
- **A request started on `/embed` gets no span and leaves no `fetch` or `xhr` breadcrumb**, since the viewer fetches the document there, the builder's preview included. Sentry records the breadcrumb as the request ends, an abort included, perhaps after Back or a link left `/embed`, so `sentryPrivacyOptions` keeps the URLs its `tracing.shouldCreateSpanForRequest` was asked there, which Sentry asks as a request starts while `tracesSampleRate` is set, and drops a later breadcrumb of any of them. `main.tsx` hands `tracing` to `browserTracingIntegration` and `init` to `Sentry.init`. `shouldCreateSpanForRequest` takes the page's path as a required second argument, so it cannot go to `browserTracingIntegration` as it is (a `tsc` error `sentryScrub.test.ts` pins).
- **Leave `tracePropagationTargets` unset.** Without it Sentry adds `sentry-trace` and `baggage` to same-origin requests alone, so the viewer's fetch of a document on another host stays a simple request; a wider list makes that fetch preflight, which a raw file host such as GitHub's may refuse.

### Build

- **Take `RouterProvider` from `react-router/dom`.** The root export of that name lacks the `flushSync` wiring and still typechecks.
- **`run.tasks` is bespoke**: its `cache.input` lists name `packages/erd-editor/dist/**/*.d.ts` by hand, so a newly typechecked sibling goes into them.

## Common Patterns

- `Component.tsx` beside `Component.styles.ts`; Emotion `css` prop, Radix Themes, `lucide-react` icons, inline SVG for brand marks lucide 1.x lacks (the GitHub mark in `ResourceLinks.tsx`).
- jotai modules export their state atoms and keep write-only `atom(null, …)` action atoms private behind `use*` hooks.
- **Buttons are gray-first, size 2**, size 1 inside the compact update-prompt card and in `/gdrive`'s save status pill. A screen's one primary is `solid` `color="gray"` `highContrast`; a destructive one is `outline` red, or ghost red in a row, never solid, since red-9 under white reads 3.9:1. Secondaries are `outline` gray, Close / Cancel `soft` gray. The sidebar's New schema and Trash are ghost gray rows (`rowButton` in `SidebarItemView.styles.ts`) with their icon on the list's text edge. Solid jade's white label reads 3.15:1, so it is avoided.
- ERD Editor (root § Common Patterns) names the tab title, the manifest's `name` and `short_name`, notices, dialogs, the callback and policy pages, the Marketplace banner and console app names. `erd-editor` stays in the IndexedDB name, the backup `format` and file name, the callback marker, the popup name, trystero's `appId` and the console project ids.

## Dependencies

### Internal

- `@dineug/erd-editor`: the two elements, `<erd-editor>` (`erd-editor.js`) and `/embed`'s `<erd-viewer>` (`erd-viewer.js`), and `engine.js`, whose `createReplicationStore()` the IndexedDB service runs headless and `emptyDocument` reads a new Drive file from. The Drive sync tests run `peer.js`'s `createPeerStore`.

### External

- `dexie` stays at `^3` on purpose: it owns users' stored documents, so a major upgrade is its own verified change.
- `@trystero-p2p/nostr` / `mqtt` load dynamically; `ERD_EDITOR_NOSTR_RELAY_URLS` at build time points nostr at private relays.
- `luxon` does all date arithmetic and formatting, the next UTC midnight included (`nextUtcMidnight` in `authMode.ts`); the list's month names and relative times are in the display language (`i18n.locale`), through the browser's `Intl`. `/gdrive` compares Drive's `modifiedTime` and `createdTime` with `Date.parse`, which also gives a file's `updateAt`.
