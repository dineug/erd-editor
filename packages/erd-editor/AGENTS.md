# erd-editor

## Purpose

The editor core, published on npm: the framework-free `<erd-editor>` custom element on `@dineug/r-html`, with a Redux-like store whose actions carry a Lamport clock version and merge through the LWW registers in `@dineug/erd-editor-schema`. `app`, `webview-client`, `replication-store-worker`, `obsidian-plugin`, which bundles it into its `main.js`, and `mcp-server` depend on it. `app` imports the DOM-free `engine.js` entry beside the element and `replication-store-worker` imports that entry alone, and `mcp-server` inlines the DOM-free `peer.js` entry into its one file, a headless collaboration peer that edits by dispatching actions instead of by a pointer; `app`'s Drive and fingerprint specs import that entry too.

The ERD scene is a Konva `<canvas>` rendered through a second r-html host (`src/konva/`); toolbar, panels, menus and the editing overlay stay DOM. The same scene components also draw the one **view**, the Visualization tab's Flow mode — the reader's own placement, zoom and rows, never in the file, the history or a peer — told which through a `GeometrySource`.

## For AI Agents

### Working In This Directory

**Engine**

- **Adding an action** touches the module's `actions.ts`, `atom.actions.ts` and `history.ts` (whose undo entry puts it in `HistoryActionTypes`) **and** the hand-kept lists in `src/engine/actions.ts`. Missing `ChangeActionTypes` compiles, then silently breaks the host `change` (autosave), collaboration and readonly. Readonly is enforced only there (`readonlyIgnoreFilter`, `hasReadonlyIgnore`), never in components. A new change type also needs a tool or an exclusion reason in `mcp-server`'s reachability spec.
- Reducers write through the LWW operators from `@dineug/erd-editor-schema` with `action.version`; a direct write wins every merge and corrupts collaborative sessions.
- **A scroll or zoom is still a change**, unlike one in a Flow view (View seams, below). Scroll and zoom (`settings.scrollTo`, `streamScrollTo`, `changeZoomLevel`, `streamZoomLevel`) stay in `ChangeActionTypes`, which following and shared views need, and the replica reports each as a `change`: every hub (`agent-hub-host`'s `joinWindow.ts`, its Kotlin port) waits for one replica save per change before `join` or `save` answers, and a missing one holds them to their caps and has `save` answer `saved: false`. With Save Scroll Information off `toJson` writes the origin as 0,0, and with Save Zoom Information off the zoom as 1, so a scroll or zoom the file keeps nothing of comes out `changed` false and the hosts write nothing and mark nothing modified (`vscode-extension`'s `erd-editor.ts`, `obsidian-plugin`'s `ErdView.ts`, `intellij-plugin`'s `ErdEditor.kt`); `app`'s Drive save drops view settings by fingerprint. A zoom moves the origin too, keeping the point it zooms around in place (`changeZoomLevelAction$`, `streamZoomLevelAction$`, `pinchZoomAction$`), so with Save Scroll Information on and Save Zoom Information off a zoom still changes the file through that origin. That stays: the origin is where the diagram was left, which is what the scroll switch saves. Neither switch covers a tab switch (`settings.changeCanvasType`), which still changes the file. The element's `change` event fires for all of them.
- **A new document starts with both switches off.** The store's initial state is `erd-editor-schema`'s `createSchema()` (`ignoreSaveSettings` 3), which is what an element given no value, a replica's or a peer's `value` before a load (`app`'s new Drive file, `mcp-server`'s `createEmptyDocument`) and every empty value a load takes show: `utils/loadValue.ts`'s `toLoadValue` turns an empty text into that document's JSON for `setInitialValue`, the `value` setter, `setDiffValue`, the replica and the peer, so the replicated `editor.loadJson` carries text any peer, a released one included, parses to the same document. A file keeps the switches it names, and one that names none (an older v3 file, a v2 `.vuerd`) parses as 0, saving both, as the release that wrote it did; flipping those would silently change what their next save writes. A SQL, DBML, AML or GraphQL import keeps every setting of the document it replaces but the view (`loadSchema*Action$`), so a source given to an element with no value, as `app`'s `convertSource` does, becomes a new document too, and one imported into a file keeps that file's switches (`useErdEditorAttachElement.test.ts`). `clear()` keeps every setting, so a cleared file keeps its switches. Text the parser cannot read, a file with merge-conflict markers, empties the document and changes no setting (r-html logs the reducer's throw), so a store that loaded nothing before shows a new document (`replication-store.test.ts`). Time Travel's preview opens on the reader's scroll and zoom whatever the switches say (`toPreviewJson`), since it is the reader's own screen; the undo of a load or a clear loads what `toJson` wrote, so with a switch off it lands where opening the file would, which every peer replays too.
- **`changed` compares values, never the file.** The replica keeps the value its last `change` handed out, or after a load takes the value the first change action finds, which holds the load's own rewrites: `setInitialValue` collects the schema GC's tombstones and runs `settleLoad` (`store-hooks.ts`) before it returns, writing at once what the hooks a load wakes write over the next 10 ms, every `ui.width*` measured again with this machine's fonts and the relationship anchors (`recalculateTableWidthHook`, 5 ms), the foreign key bits, and each relationship's `identification` and `startRelationshipType` (10 ms), so a pan replayed right behind the load is no edit. A new hook on any action a load dispatches, its `editor.clear` or `editor.initialClear` and the `editor.validationIds` a replica's GC dispatches after it included, joins `settleLoad`, as `store-hooks.test.ts` holds by recording what both load generators and a replica's `setInitialValue` reduce, and joins the fields `app`'s `toFingerprint` and `toDriveFingerprint` leave out (`utils/documentFingerprint.ts`, with a case in `service.test.ts`; `packages/app/AGENTS.md`), since `app` also fingerprints a converted source and another tab's Drive base, which carry no `settleLoad`, and would count the hook's write as an edit. A file an older release or another machine wrote, a v2 `.vuerd`, a byte order mark or a hand edit all differ from that value from the load on, so a host that compared bytes with its file would take the first scroll for an edit. A load that lands while a change is pending reports that change with `changed` false. `engine/replication-store.test.ts` pins both switches, a zoom with only the scroll switch on (which saves the origin it moved), a new document and a new empty file (which save neither), a file without the field (which saves both), a tab switch, another machine's widths, a file without the origin and a scroll or zoom in the first 10 ms of a stale file.
- Reader-only state (`editor.views`, `visualizationMode`, `handTool`, `zenMode`, `openMap`) is in no list, so it is never saved, undone or sent to a peer; `engine/actions.test.ts` pins the ten `editor.view*` types and `editor.changeVisualizationMode` out of all of them.
- **View seams** (`rx-store.ts`): while `getActiveView` finds one, `viewActionRedirect` rewrites `settings.scrollTo` / `streamScrollTo` / `changeZoomLevel` / `streamZoomLevel` into their `editor.view*` twin (not `Tag.shared` / `Tag.following`), and `viewIgnoreFilter` drops `ViewIgnoreActionTypes` (readonly's list minus `editor.loadJson` / `editor.clear`), letting `Tag.shared` reach the store. `undo` / `redo` no-op while a view is active.
- **Both seams classify a batch by the state it enters with**, so leaving a view and moving the document are two dispatches — `goToErdTable` (`erd/canvas/table/goToErd.ts`) is the model; `e2e/specs/visualization-flow.spec.ts` asserts what the host hears.
- **The foreign key columns a relationship creates are named in one place**, `toForeignKeyNames` (`engine/modules/relationship/fkColumns.ts`), which the pointer draw (`selectTableAction$`) and `addRelationshipAction$` both run: a key of one word (`id`, `ID`, `uuid`, `id2`; `isSingleWord`) gets the parent table and an underscore in front, a key of several words (`member_id`, `userId`, `UserID`) or equal to the table name keeps its name, and a name the child already holds is numbered `_2`, `_3`. Only an equal name escapes the prefix: a key of one word that holds the table name gets it too (`user.userid` gives `user_userid`, `회원.회원번호` gives `회원_회원번호`), as the owner decided. Any character but a letter, mark or digit splits words, so `_id` and `order-no` keep theirs, and words split where camelCase splits them, so `IDs` and `UUIDv4` do too while `Ids` is one word, as is a name in one case (`memberid`, `USERID`: `members_memberid`), and where a letter without case (`\p{Lo}` or `\p{Lm}`: Hangul, kana with its `ー`, Han) meets a cased one, either way, so `회원ID`, `ユーザーID`, `用户ID` and `IDカード` keep theirs while `회원번호` is one word; digits and marks are passed over when reading case, so `SHA256sum` is several words and `md5sum` one. The table name is used as written, dots and spaces included (`public.users` gives `public.users_id`), as the owner decided: such a column makes valid DDL only under a quoting `bracketType`, where every generator also keeps the whole name in the relationship's constraint (`"FK_public.users_TO_orders"`). Unquoted, SQL Server, Oracle, MySQL, MariaDB and PostgreSQL give that constraint the table part alone (`FK_users_TO_orders`, Code generators below), SQLite writes it unnamed, and Snowflake and Databricks keep the whole name (`FK_public.users_TO_orders`). `fkColumns.test.ts` pins each case. Relating existing columns (`erd_link_columns`, the importers, duplicates) renames nothing. A copy of a serial key takes the integer type it stores, whatever the data type sync, by `toReferenceDataType` (`relationship/referenceType.ts`, DOM-free for the peer): PostgreSQL's own `smallserial`, `bigserial` and `serial2` / `4` / `8` by PostgreSQL's types under any database, a bare `serial` by `settings.database` (`integer` in PostgreSQL, `bigint unsigned` in MySQL and MariaDB, kept elsewhere), a whole name only, in capitals when the key's is, and no saved document migrated (owner decisions); that sync (`table-column/utils/dataType.ts`) maps a key's change into its foreign keys the same way and carries a foreign key's change back to its key unless the key's type is serial, which keeps it and stops the change there. `mcp-server`'s `erd_add_relationship`, `erd_change_column_data_type` and `erd_set_relationship_data_type_sync` descriptions (`tools/copy.ts`) state these rules to agents, so they change with the code.
- Keep host integrations on `ErdEditorElement`. `webview-client`'s `mountWebview` sets the import callback only when a host passes `importFile` (VSCode does, IntelliJ does not), so the built-in `<input type=file>` is IntelliJ's only import path.

**Scene sources and views**

- **`GeometrySource` picks coordinates, shown set and sort channel at once.** Pure functions take a trailing `source = 'document'`; scene components read `useSceneSource(ctx)`. Each scene root (`Erd`, `ErdViewer`, `AutomaticTablePlacement`, `TimeTravel`, and `FlowScene` in `VisualizationFlow.tsx`) provides it **inside a wrapper, never on the root it returns**: `useProvider` attaches to the parent element, so siblings would inherit it.
- Outside any provider, code that must follow the reader (zoom generators via `getActiveTransform`, the view reducers) reads `getActiveView`.
- **A scene writes to the slot it reads**: `sceneScrollToAction(source, …)`, `changeZoomLevelAction$(value, source)`, `moveAllAction$(dx, dy, source)`, `kind` on a view payload. An unnamed scroll or zoom lands on the active view; an unnamed `moveAllAction$` goes to the document, and an open view drops it.
- **`viewLayout.ts` decides what a view shows**: only the tables in `positions` (nothing until a layout lands), **no memos**, relationships with both ends shown, rows per `showMode`; `settings.show` and `columnOrder` do not apply. Hover and pin are module observables keyed on `editor.id`, never actions.
- **`flowLayout.tsx` is the one place a Flow placement is asked for** (`TablePlacement.viewLayered`). Landings are cached under `placedKey` — centers, show mode, the doc's id lists, **never `positions`**, or the loop re-asks on its own answer. Narrow or widen only through `components/flowCenters.ts` or `focusFlowTableAction$`.
- `toHints` (`services/elk-layout/elkGraph.ts`) normalizes coordinate hints; handed raw coordinates, ELK's INTERACTIVE layering reads one document row as one layer per table.

**Relationship geometry**

- `draw-relationship/sort.ts` is the whole geometry pass, routing (`route.ts`, `nudge.ts`) included because it needs every table and route; `pathFinding.ts` only draws.
- **A rendering-only value goes in the `WeakMap` sort channels of `draw-relationship/index.ts`, never a new schema field** — anchors are schema fields and serialize. One channel per source; a view keeps its anchors there, so `setAnchors` writes the entity only for the document. `clearSortChannel` clears per connector, since channels are module-wide.
- View channel setters bump `viewVersions` **only on an actual change**; an unconditional bump redraws every static connector on each drag sort.
- **A connector shows its referential actions at its child end** (`relationship/RelationshipActionLabel.tsx`, an owner decision of 2026-10-03), after erwin's notation: `D:` for ON DELETE, then `U:` for ON UPDATE, each only when set, with `C`, `R`, `SN`, `SD`, `NA` (`utils/referentialAction.ts`), in the code face and the route's colour, lit with it on hover (the group's `hovered`, which the labels alone read, and `hoverRelationshipMap`), on a box of the canvas colour that clears the widest marker: over a route leaving sideways, reaching away from the table, and right of one leaving up or down. `RelationshipGroup` draws every label after every route, so a connector crossing one runs under its box; drawn inside each connector's own group, a label lay under every connector drawn after it. The box is sized from the code face's advance (`0.61` of the size, as the alternate key marks are), so the text is never measured. It is the document's notation alone, a view drawing no distinction by kind, and a zoom that draws a table by its name alone (`isHighLevelTable`) draws none. A hover spells the clauses out in the canvas's native tooltip, the `title` the stage container takes while the pointer is on the connector (`Relationship.tsx`), as the toolbar's buttons name themselves, written again on each render so a peer's change under a resting pointer shows; it shows with the label hidden too, and leaves with the pointer or the connector. View Option's Referential Actions hides the label: it sets `Show.hideReferentialAction`, the one bit that hides what it names, so every document, those saved before it included, shows the labels until a reader turns them off. Showing or hiding them moves nothing, so the sort hook skips that toggle (`isLabelToggle`) and the table size key masks the bit out.
- The sort hooks (`engine/modules/relationship/hooks.ts`) open a 5 ms window for a `Tag.drag` action and sort in a microtask otherwise; a timer loses to the next frame, which draws moved tables with stale connectors.

**Keys and alternate keys**

- **A key the columns declare is never an index entity.** `utils/tableKeys.ts` derives, at render time, the primary key and each unique column (`getColumnKeys`, the read-only rows the Indexes tab lists above a separator, each with a lock where an index has its remove button) and the alternate keys: every unique index over two or more of the table's columns (`getAlternateKeys`), whose member columns carry `AK<n>.<m>` by their place in `indexColumnIds` (`getAlternateKeyMarks`). A single-column unique index and a UQ flag, the same constraint in two spellings a Snowflake round trip swaps, carry no number. Nothing is stored but the `Show.columnAlternateKey` bit, off in every existing document, so no diagram widens until a reader shows the marks.
- **AK numbers follow the table's column order, never `doc.indexIds`**: keys compare by the positions of their columns in key order, a prefix first, the index id last. An undo re-adds an index at the end of `doc.indexIds` and peers append concurrent adds in arrival order, so numbering by that list swapped numbers on undo and differed between collaborators (`tableKeys.test.ts` pins both); reordering the columns may renumber instead.
- **A mark always stands last in its row, in no column order.** It is derived and never edited, so it is no `ColumnType`, no `FocusType` and no entry of `settings.columnOrder`: `getAlternateKeyMarkX` puts it one margin past the last cell `getColumnCellSlots` lays out, whatever the order, and the cells keep `getColumnCellsX`, so the column names stay in line with the header name and the edit overlay and the drag ghost never move for it. Its `k-text` does not listen, so a press on it is a press on the row, as between two cells; keyboard focus, the cell editor, copy and paste walk the order and never reach it. Graph mode's DOM card (`visualization/table/`) draws it last too.
- **The marks widen only the tables that carry one.** `calcAlternateKeyWidth` sizes the room after the last cell from the longest mark at `COLUMN_ALTERNATE_KEY_CHAR_WIDTH` per character (the code face at the cell size, no text measure, so the peer sizes it too), kept in `ColumnWidth.alternateKey` and added to the row sum like any other cell. The seven actions that add, drop, reshape or renumber a key (the five index ones, `moveIndexColumnAction`, and `moveColumnAction`, which renumbers) are in the sort hook's `layoutActions`, which bumps the width generation the size cache keys on, but the hook lets them through only while the bit is set, and they are in `isDocumentOnly`, since a view's geometry sees none of them.
- **A table reads only its own indexes.** `getTableIndexIds` groups `doc.indexIds` by table once per add or drop and caches the grouping on the list, so a sort measures every table in one pass over the indexes, not one per table. The two index reducers that push and splice the list call `invalidateTableIndexes`; any other in-place write to it must too, while a replaced list or entity map is caught by identity. An observer keeps `doc.indexIds.length` and its own indexes' fields, so with the bit set an index add or drop redraws every table and any other index change only its own (`tableKeys.test.ts` pins both).

**Table Properties**

- **One fixed box for all three tabs** (`erd/table-properties/TableProperties.styles.ts`): 1040 by 600 at most, hung from the palette's line 60px under the editor's top and shortened by `max-height: 100%` on a low host, so switching tabs never moves the frame. The header holds the title, a chip per table opened lately and the close button, the one control the keyboard reaches; it hands focus back with `focusEvent` on `nextTick`, or the keyboard falls to the page and the shortcuts stop. It keeps a Space keydown from the editor root, whose hand tool binding cancels it and with it the button's press. Escape and a press on the backdrop close it. The editor's `readonly` reaches it through `Erd`'s prop, as it reaches `Toolbar`: a badge after the title, no add row or remove button, names that take no typing, every box disabled and the order fixed. That is display only; the store's readonly filter stays the guard.
- **The keys and the Columns heading stick to the body's top edge** (`TablePropertiesIndexes.styles.ts`): one body scrolls the whole tab, and the left pane sticks inside `leftTrack`, which `align-self: stretch` makes as tall as the columns beside it and only as tall as its own rows once the panes stack, so the keys stay beside a long list and scroll away above one without a container query, which the browser floor lacks. A key list taller than the body shows its last rows at the end of the scroll. `columnsHead` reaches over the body padding as the order does. The browser counts a box under a sticky band as shown, so each checkbox carries a `scroll-margin` of the stuck heading and the tallest order (`INDEX_ORDER_MAX_ROWS` rows), and Tab never stops on a box the order hides; a mouse focus scrolls nothing.
- **The Index order sticks to the body's bottom edge** (`order` in `TablePropertiesIndexes.styles.ts`): it sticks 12px past the body's padding edge, pads its rows back by as much and takes that padding out of the flow with a negative margin, so a stuck order hides the rows under it and one in place adds no scroll height. Both it and `scrollbarArea` in `TableProperties.styles.ts` read that padding from `TABLE_PROPERTIES_BODY_PADDING` (`constants/layout.ts`). Its rows carry the canvas's `AK<n>.<m>` marks, numbered as `getAlternateKeyMarks` numbers them. A row's `class` stays one constant value: the drag adds `dragging` and `none-hover` by hand, and r-html strips a class it did not set whenever the bound value changes, so the read only state is the `data-readonly` attribute instead.

**Peer store (`peer.js`)**

- **The peer graph runs in Node with no DOM and no bundler of its own**: `mcp-server` inlines what `src/peer/index.ts` reaches into one file, so that graph obeys the two rules root `AGENTS.md` gives under `pnpm peer-graph`, no browser global and no package outside its allowlist besides the workspace libraries it inlines. `src/peer/imports.test.ts` holds the sources to them in `pnpm test` and `pnpm peer-graph` holds `dist/` after `pnpm build`; their allowlists change together. A shared helper that starts reaching konva, shiki, elkjs, comlink or a worker spawn is how that breaks.
- **The entry carries values, never tools.** `src/peer/index.test.ts` pins its key set and the absence of the flat `actions` map, whose `changeZIndexAction` would come from whichever module spread last. Tool names, the registry, argument validation, reading and the reachability lists belong to `mcp-server`; `engine/no-agent-concepts.test.ts` fails on any of them reappearing in `src/`.
- **Six keys are there for specs alone** — `createEngineContext`, `ChangeActionTypes`, `StreamActionTypes`, `SharedFollowingActionTypes`, `SelectType` and `settingsActions$`; `defaultToWidth` serves those specs and also sizes tables for `erd_list` (`mcp-server`'s `src/tools/outline.ts`). `mcp-server` holds each tool declaration to what the engine measurably does, so its specs need the real context, the real text measure, the real type lists and the real generator barrel; a `./peer/testing.js` subpath would make a fourth entry and split the chunks again. `mcp-server`'s `src/peerSurface.test.ts` proves no key is dead. `app`'s Drive and fingerprint specs import the entry too (`createPeerStore`, the table, column and settings barrels, and `SharedFollowingActionTypes`, which `documentController.test.ts` holds `NON_EDIT_ACTIONS` to), so a change to the key set runs `app`'s `test` beside `mcp-server`'s.
- **The labelled undo unit is the peer's own bookkeeping**, not the engine's: `dispatch(actions, { label })` records one unit, `group(label, run)` gathers the dispatches `run` makes into one unit under its own label (a group inside a group joins the outer one, a group that dispatched nothing leaves none, and `undo`, `redo` and `setInitialValue` throw inside one, since the unit would no longer match the history), `undo` pops the newest that made an entry and names the labels it passed over, and `setInitialValue` forgets all of them. The engine's history knows only entries.
- **Stream buffer option.** `createRxStore(context, { manualStreamFlush })` and `createSharedStore(store, config, { manualStreamFlush })` close a stream group (colors, memo resizes) on `flushStreamBuffers()` instead of `groupByStreamActions`' 200 ms quiet period, through `flushOnNotifier` over a `Subject` the store owns. Each store owns its tick count too: one in the rx-store's single history stage; `FLUSH_TICKS = 2` in the shared store, whose compressor stands on each side of the circuit breaker and whose second stage arms too late for the first tick. So `stream-flush.ts` flushes history first, then the outbound pipe, and knows neither the count nor an rxjs type. Without the flag the rx-store's `flushStreamBuffers` is a no-op and the editor keeps its timing: a stream edit reaches peers after the two stages' 200 ms each, 400 ms. The shared store's still works there (`quietPeriodOrNotifier`, the quiet period or the flush, whichever comes first), so a host can send a drag still held back before it lets the store go; `obsidian-plugin` does when a tab closes, so the other tabs of its file keep what it held. The shared store takes it as an internal third argument (`SharedStoreInternalOptions`), so neither `SharedStoreConfig` nor the config `getSharedStore` takes carries a stream option.
- `flushOnNotifier` and `createSharedStreamActionsCompressor` are deep-imported and stay out of the `rx-operators` barrel: `rx-operators/index.test.ts` pins the barrel's export set, as it keeps `readonlyIgnoreFilter` out.
- **`createRxStore`'s internal `observable` option** (default true) keeps the state a plain object. r-html's reactive proxy reads `value instanceof Node`, a `ReferenceError` in plain Node; the replica store never hit it because it already ran with observation off. The peer passes false and first dispatches `changeViewportAction({ width: 0, height: 0 })`, so a load never reaches the pull's view lookup. `RxStoreOptions` is not public surface.
- **A replicated sort sends `table.moveTo`, never `table.sort`.** `sortTable` places by each replica's own `toWidth`, so replaying it lands tables apart; `sortTablesToMoveAction$` runs the reducer on copies of the live tables and sends the absolute points in one undoable batch. An import's `table.sort` is safe because the widths travel inside its `loadJson` payload.

A relation field whose name is taken is numbered (`user2`), except that a relationship outside that rule whose name another one outside it took is dropped. The importer pairs a singular field with the one reciprocal named `by` and its name before its other rules, the longer name first, then once more with the digits a numbered name ends in dropped (`pairByName` in `convert.ts`), so these documents import back with as many relationships, except where numbering leaves names alike: several relationships of one pair that no foreign key names, two keys giving one name on a one and a many side (`buyer_id` beside `BuyerID`), or a stem ending in a digit that numbering repeats (`buyer2_id` beside `buyer_id` where the parent holds a column `orderListByBuyer`).

A primary key without the NOT NULL flag still reads as NOT NULL, as in `typeorm.ts` and `sqlalchemy.ts`.

  - `schema-sql/`: a comment, and a name SQL Server's `sp_addextendedproperty` takes, is written through `toStringLiteral` (`utils.ts`), quotes doubled as the importer reads them, the `MS_Description` call included (`packages/schema-sql-parser/AGENTS.md`); `Databricks.ts` escapes a quote and a backslash with a backslash instead, the form every Spark release reads (only the newest read a doubled quote). The importer reads that form back by Spark's rules when the document's database is Databricks: `loadSchemaSQLAction$` hands `settings.database` to `schemaSQLParser`, every backslash then escapes the character after it, and a `DEFAULT` literal or a STRUCT field's `COMMENT` inside the type goes back as `'it\'s'`, so import, Databricks export and import again agree.   - `schema-sql/MSSQL.ts` names an `MS_Description` call's schema at level 0 as `'schema'`, its table at level 1 and its column at level 2 (an owner decision of 2026-10-04: SQL Server refuses `'table', 'dbo.users'` for the table an unquoted `CREATE TABLE dbo.users` makes; SQL Server 2022 ran this output the same day for `sales.users` and `users`, unquoted and double-quoted, and `sys.extended_properties` kept every comment on its table and column). An unquoted name splits into parts, the last the table and the one before it the schema, `dbo` where it gives none (the default schema of the database owner, which the export assumes). Two owner decisions of 2026-10-05 follow: each part loses one enclosing pair of brackets or double quotes (`[sales].[users]` gives `'sales'` and `'users'`, `[Order]` gives `'Order'`), and the part before the schema names the database whose own procedure the calls run (`EXECUTE shop.sys.sp_addextendedproperty`), since the levels name no database and a call acts on the database of its procedure, so a script connected to any database finds `shop.sales.users`. The rest reads a part as SQL Server does: a dot splits only outside a pair (`[sales.v2].users` is `users` in schema `sales.v2`; split there, `[sales` before the procedure would leave a bracket open that swallows every later batch); a doubled closing character inside the pair is one (`[x]]y]` gives `'x]y'`); the database goes before the procedure as typed (`[my shop].sys.…`), and only as a regular identifier or one delimited name, else it is dropped (`o'shop.o'sales.users`, whose `CREATE TABLE` fails too, would open a quote); a fourth part, which `CREATE TABLE` refuses (Msg 117), is dropped. Either way level 1 holds the name the importer gives the table (`sales.users` quoted; `users` for `[sales].[users]`, `[sales.v2].users` or `shop.sales.users`, `x.y.z` for `[x.y.z]`), so the comments survive the round trip, except `[x]]y]`, which the importer reads as a table `x` with no columns. A column name goes to level 2 as typed, so a bracketed one in an unquoted export (`'[Order Id]'`) is refused by SQL Server (Msg 15135) and matches no column the importer reads (`Order Id`), a case the owner has not decided. `findCommentTable` reads a call naming an unquoted `dbo.users` whole at level 1 by its last part, so a file an older export wrote (`'user', dbo, 'table', 'dbo.users'`, which SQL Server refuses) keeps its comments, its `CREATE TABLE dbo.users` reading back as `users`.
  - `schema-sql/`: a column default goes out as stored, but in parentheses where the database reads that expression only inside them (`formatDefault`, `utils.ts`), since the importer keeps a default without the parentheses around it (`packages/schema-sql-parser/AGENTS.md`): MySQL wraps anything but a literal or the current time (with an `ON UPDATE` written into the default by hand, which stays bare), and, from the column's type it is handed, any default but `NULL` on a BLOB, TEXT, JSON or spatial column (a type that opens with `LONG`, which MySQL reads as MEDIUMTEXT or MEDIUMBLOB, among them) and the current time on any column but a TIMESTAMP or DATETIME, which MySQL reads only in parentheses; MariaDB wraps anything but a literal, the current time, a function call or a name, SQLite anything but a literal or a name, and PostgreSQL only an expression holding a word its `DEFAULT` refuses outside them (`AT TIME ZONE`, `AND`, `IS`, `COLLATE`, `= ANY`, …). SQL Server, Oracle, Snowflake and Databricks take an expression bare, so their output is the stored text, and so is a default its database takes bare.
  - `schema-sql/`: an unquoted table name with a dot is schema and table, so SQL Server, Oracle, MySQL, MariaDB and PostgreSQL build an automatic constraint or index name from the part after the last dot (`tableNamePart`, `utils.ts`): `sales.users` writes `PK_users`, `UQ_users_email`, `FK_users_TO_orders` and `IDX_users`, which each of them refused with the dot in it. SQLite names no constraint, writing its primary key, unique and foreign key clauses bare, so the only automatic name it builds from the table part is `IDX_users`, which it refused with the dot in it too. `splitsTableName` names those six for the Indexes tab's key rows (`getColumnKeys`), which keep the whole name under Snowflake and Databricks, as their DDL does. Two schemas holding one table name repeat the primary key and unique names, kept in the table's schema by every database that names them, and number the foreign key and index names across the export as before; SQL Server 2022, Oracle 23ai Free, MySQL 8.4, MariaDB 11, PostgreSQL 17 and SQLite ran that script clean. Those six number an automatic index name, and the five that name foreign keys an automatic foreign key name, that repeats an earlier one but for case too, quoted or not (`autoNameIgnoreCase`, `utils.ts`), as the owner decided: `sales.users` and `hr.Users` referenced from `sales.orders` write `FK_users_TO_orders` and `FK_Users_TO_orders1`, where those five refused the unnumbered pair and ran the numbered script clean, and SQLite, which writes no foreign key name, ran either script; MySQL and MariaDB refused it for a quoted `users` and `Users` too, since a foreign key's index name folds; PostgreSQL and Oracle ran that pair either way, and SQL Server and SQLite refuse its second table. A name differing in more than case keeps its bytes; Snowflake, Databricks, Oracle's sequence names, the code generators and the importers number through `autoName`, which compares exactly. Oracle writes every index on a dotted table beside it, automatic or named (`sales.IDX_users`, `sales.idx_users_name`), since unqualified it lands in the current user's schema, where one name given in two schemas clashes, and creates an `autoIncrement` column's sequence and trigger there too, named from the table part (`sales.SEQ_users`, `sales.SEQ_TRG_users`, whose body reads `sales.SEQ_users.NEXTVAL`; Oracle ran it as SYSTEM and as each schema's owner), the trigger name numbered against the sequence names, never the earlier triggers; SQLite writes `CREATE INDEX sales.IDX_users ON users` and `REFERENCES users`, the only spelling it reads, a foreign key resolving in the child table's schema; in both an index name the user already qualified keeps its own schema. A quoted name is one identifier and keeps the whole name (`"PK_sales.users"`).
  - A relationship's `onDelete` / `onUpdate` (`ReferentialAction`, `none` by default) write no clause while unset, so the output stays byte for byte what it was. `referentialActionSupport` (`schema-sql/utils.ts`) names per database what its DDL writes and drops the rest, leaving the database default: MySQL and MariaDB refuse SET DEFAULT, SQL Server has no RESTRICT, Oracle writes only ON DELETE CASCADE or SET NULL, Databricks only NO ACTION. The ORM generators follow the same table for `settings.database`, `drizzle.ts` for the dialect it writes (PostgreSQL's where it borrows pg-core, which drizzle-kit turns into PostgreSQL DDL), `typeorm.ts` also leaving SET DEFAULT out (TypeORM writes it `DEFAULT`), and `jpa.ts` writes none (JPA has no option, and the generator stays plain JPA, never Hibernate's `@OnDelete`); `dbml.ts` and `aml.ts` write every action, the documents being vendor-neutral, and `aml.ts` writes a relationship with actions as a `rel` statement, since AML hands an inline relation's properties to its attribute; its `formatTable`, which writes no `rel` statement, keeps the relation inline without them. The relationship context menu offers every action and notes one the current database would drop (`not in MySQL`), so the document stays vendor-neutral and the user sees why the DDL has no clause.
