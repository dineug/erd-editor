# dictionary

## Purpose

`src/components/dictionary/` holds the Dictionary tab, the sixth, whose toolbar button draws lucide's `book-a` between Code Generator and Settings (owner decisions of 2026-10-20): a bar with the four sheets (the words, the terms, the domains and the checks over them), a search, the row buttons and the CSV file buttons, a `@dineug/grid` grid of the sheet shown, and a status line under it. The rows, their writes, their refusals and the checks belong to the engine (`src/engine/modules/dictionary/`, whose rules are under Dictionaries and derived names in `src/engine/AGENTS.md`). This file holds how the tab puts them on the grid: the rows a version shows, how a commit resolves to row ids, where a version comes from, where a check leads and how the other sheets mark what the checks find, the keys the tab passes and stops, the grid's theme, a read-only document, and how a CSV file comes in and goes out. The file's layouts and bytes are the codec's (`src/utils/dictionary-csv/`, Dictionary CSV in `src/utils/AGENTS.md`). What the grid keeps and what its host keeps, its handle and its commits are in `packages/grid/AGENTS.md`.

## Making a Change

1. **Read the files on the other side.** A change to how the tab drives the grid (`version`, the handle, `onCommit`, `isEditing`) reads `packages/grid/AGENTS.md`, and a change to a write reads `src/engine/AGENTS.md`. `stopsAtPanel` (`src/utils/keyboard-shortcut/index.ts`) is shared with the Explorer, the diff tree and the color picker, so a change there reaches this tab's keys; a change to the find chord reads `src/components/explorer/AGENTS.md`.
2. **Import the grid from `src/components/` alone.** `@dineug/grid` is a devDependency the build inlines, so its code ships in the element's `index.js` and the UMD build and counts in `pnpm size`. The peer graph must never reach it: `src/peer/imports.test.ts` fails on a graph that reaches `components/` or names a fifth inlined library, and `pnpm peer-graph` on a browser global in what `peer.js` reaches.
3. **Run the package's checks.** Making a Change in the package file (`packages/erd-editor/AGENTS.md`) gives the test task and the coverage run. `Dictionary.browser.test.tsx` runs in real Chromium in that task.

## Rules

### Mounts and the window's own place

- **The tab mounts again on every visit.** Only the ERD tab is cached (`ErdEditor.tsx`), so what a reader left on a sheet lives in `dictionaryViewOf(app)`, a `WeakMap` over the store as `schemaSQLViewOf` is: the sheet shown, and per sheet its search, selection, scroll and column widths. None of it is in the store, the file, a change event or a peer, and it lasts until the element goes, one per editor. Each value is frozen and replaced whole, so a watcher hears one change and the grid is handed no proxy.
- **Each sheet keeps its own search.** A sheet's kept selection and scroll count the rows its search shows, so a new search drops both and the active cell goes back to the first cell.
- **The tab keeps the widths.** The grid draws a resized width only while its host's columns hold it (`packages/grid/AGENTS.md`, The host keeps every width), so `onColumnResize` writes it into the view, and the sheet opens its columns at it on the next mount.
- **One grid per sheet.** `repeat([sheet])` mounts a new grid on a sheet switch, since a grid's selection, scroll and rows belong to one sheet. Each mount holds a session: its `SheetRows`, the check sheet's checks, the handle (a stand-in that does nothing until `onReady`) and the last selection, which the tab keeps since `GridHandle.select` does not echo the host's own change. The render reads the sheet shown from the tab's observable state, never from the session, since two empty sheets open on the same counts and a switch between them would change nothing else the render reads.
- **`onReady` puts the reader back.** It selects the kept selection held inside the rows shown now, notes its active row, scrolls back to the kept first cell and focuses the grid. `restoreScroll` goes to the last cell first, since `scrollTo` scrolls the least distance, so the way back up leaves the kept cell first in view. The focus lets typing before any gesture reach the first row.
- **The columns change only with what they are made of.** The tab hands the grid a new columns array only when the sheet, the read-only state, the widths object or the display language's `t` changes, since a new array lays the grid out again and redraws both of its layers.

### Rows and versions

- **Read a version's rows where it is raised, never in the render.** An entry sheet's rows are `doc.<kind>Ids` in their listed order with the search applied (`sheetRowIds`), and reading them walks every row through the store's proxies. The render hands the grid the version and calls `rows.receive(version)`, after which the rows of older versions are let go.
- **A search reads its sheet's own fields** (owner decisions of 2026-10-20): a word's name, abbreviation, English name and description; a term's name, physical name and description; a domain's name, data type and description. It matches a part of the text, composed and in lower case. A line break joins the fields, so a match never runs across two of them.
- **Every batch raises versions the same way.** `store.subscribe` hands the tab each batch, a local edit, a peer's batch, an undo and an import alike, and `bumpedSheets` names the sheets it raises: all four for any `dictionary.*` action or `editor.loadJson`, `initialLoadJson`, `clear` or `initialClear`, since a term shows its domain's name and the checks read every dictionary; the check sheet alone for a table's or a column's action, a name view switch and a lock change, since its targets follow the view; none for any other. The tab raises the sheet it shows, and a new search raises it too.
- **Select before raising.** A selection the tab hands the grid (on a new search, or once the batch Add Row or Delete Rows sent lands) is selected and noted as the active row before the version goes up, so the raise reads the active row's id from the new rows.
- **The check sheet lists again once a frame.** `checkRows` runs `listDictionaryChecks` over the whole document, so only a mounted check sheet asks for it, on the next animation frame after a batch raises it and once however many batches come before that frame, since a peer's drag sends one every frame. Its version goes up by one each time. A display language switch raises it too, though it sends no batch, since its search matches the text its cells show in the language shown. Its three columns (the kind, the target, the detail) are read-only in every document, since a check is read off the other sheets and the tables. The target names a table, and a column after its table and a dot, as the name view does, unnamed where the view shows no name (`nameOf`, `src/components/erd/AGENTS.md`, Name views), so its search finds a column by the logical name the logical view draws.

### Commits

- **An edit commits to the row it opened on.** An edit opens only on the active cell, so `source: 'edit'` resolves to the active row's id, which a peer's removal above it cannot move. A paste and a clear resolve by the rows of the version the grid last received, row by row, since the grid reads its ranges over the rows it drew; a row past the end is a new row, added in order.
- **Read the active row's id at six moments.** As `onReady` selects; on each `onSelectionChange`; on a raise while none is noted, from the new rows at the active index, as when rows come to an empty sheet; on a raise with no edit open, the same way, while an open edit keeps the row it opened on; after an edit commits, from the rows the grid received; and in the capture phase of a `keydown`, `dblclick`, `compositionstart` or `beforeinput` on the sheet's container, before any of them opens an edit (`settle`), the last for text an emoji picker or dictation inserts with no keydown, which opens an edit too (`packages/grid/AGENTS.md`). Without the last three, an idle active cell under a peer's removal above it, or an edit cancelled after rows moved under it, would send the next edit to the neighbouring row.
- **A row a peer removed drops the commit.** A commit naming a row the document no longer lists sends nothing and opens the `dictionary.toast.rowRemoved` toast.
- **A term's domain cell takes a domain's name.** It writes the id of the first listed domain of that name, and `''` for no text. Text that reads as the name the cell showed keeps the link the row holds, a removed domain's included, which shows as nothing, so pasting back what a cell showed never unlinks. A clear (Delete or Backspace) unlinks whatever the cell linked, a removed domain too, since it asks for an empty cell and would otherwise leave the unknown domain's mark on a cell that shows nothing.
- **One refused row drops the whole commit** (an owner decision of 2026-10-20). A name another listed row of the sheet or another row of the commit holds, or a domain name no listed domain has, sends none of the commit, so one commit stays one dispatch and one undo. Each reason opens one error toast, `dictionary.toast.duplicateNames` or `dictionary.toast.unknownDomainNames`, with the count of rows it refused and the first three names, its text counting rows too: "2 rows share a name with another row (X)" reads true whether the other row is listed or in the same commit, and "3 rows name an unknown domain (X)" where three rows name one. The names are listed by `Intl.ListFormat` as `unit`, with no "and", since the count says when there are more, and each is isolated under a right-to-left language. Its key names the count and the names (Toasts in `src/components/AGENTS.md`).
- **What the grid refuses opens a toast** (an owner decision of 2026-10-20). `onReject` reaches `reportGridRefusal`, one toast per reason under its own key: `dictionary.toast.multiRangeCopy` and `dictionary.toast.tooManyCells` are errors, since the copy, clear or paste did nothing, and `dictionary.toast.pasteBeyondColumns` carries no tone, since the paste wrote the columns the sheet has. It opens only once the paste's commit landed in the same paste event: a paste that wrote nothing, in a read-only document, on the check sheet or with its commit refused, says nothing of the columns past the last, the refusal's own toast saying why where there is one.
- **The rest is one dispatch.** `commitDictionaryCellsAction$` adds the rows past the end and writes the others, a term's composed physical name and the types of the columns linking a changed domain included, so one undo takes the commit back (`src/engine/AGENTS.md`).

### The check sheet and the marks

- **A check leads to what it names** (owner decisions of 2026-10-20). A double click or Enter on the check sheet goes to the check of the active row, which the last `onSelectionChange` reported or `onReady` selected. The grid hands its host no double click of its own, so the tab hears the sheet container's `dblclick` after the grid's, and counts one only on the active cell, under the focus textarea the grid keeps over it (`packages/grid/AGENTS.md`, The focus textarea is the editor). So a double click on a header, a column edge, a scrollbar or below the rows goes nowhere.
- **A dictionary row shows on its own sheet.** The tab switches to that sheet with the cell the check reads selected, the name or a term's domain, and its row first in view: it keeps that selection and scroll for the sheet, and the grid the switch mounts selects them (`GridHandle.select`) and scrolls to them (`restoreScroll`, `GridHandle.scrollTo`) on `onReady`. A search that hides the row is cleared first, and a row the document no longer lists goes nowhere.
- **A table or a column goes to the ERD tab** through `goToErdTarget`, one jump by the jump rule (`src/components/erd/AGENTS.md`), which rings the cell the check reads, the name, the logical name or the domain, or the cell the name view draws in its place. The grid that held the keyboard goes with the tab, so `forceFocusEvent` hands it to the editor's root.
- **Enter stops at the sheet.** Microtasks run between the listeners of a user's event, so the tab has unmounted before its root's listener would stop the press, and the editor's root would read it as `edit` on the cell the jump focused.
- **The other three sheets mark what the checks find** (`getCellStyle`, owner decisions of 2026-10-20): a name another row of its sheet holds, a term's domain no listed domain is and a forbidden word in a term's name are errors, `dictionaryErrorForeground` on `dictionaryErrorBackground`; an unregistered word or a synonym in a term's name is a warning, `dictionaryWarningForeground` on `dictionaryWarningBackground`. A physical name the dictionaries would give otherwise is a warning too, but only a table or a column has one, which the canvas marks (`src/components/erd/canvas/table/dictionaryMarks.ts`). A cell takes the loudest level its checks find (`markOf`), and a check whose source sheet is empty finds nothing, so an empty dictionary marks no cell.
- **A mark is read as its cell is drawn.** `sheetCellMark` runs the row's checks of that one field over the dictionaries' indexes, so a draw reads only the cells in view, and a dictionary's write raises every sheet's version, which draws them again. The tab hands the grid a new getter only once the four mark colours change (`toCellMarks`), since the grid draws again on a new getter. A mark shows in a read-only document too, its fill in place of the read-only one, and the check sheet marks nothing.
- **Each level's text keeps 4.5:1 on its own fill** in every theme, which `src/themes/radix-ui-theme.test.ts` holds (the dictionary marks).

### The bar's buttons and the status line

- **The bar wraps where its line is too narrow.** The tab clips what overflows it, so a narrow pane or a long language would hide the file buttons, the only way to a CSV file: the row and file buttons move to a line of their own, pushed to its end, and wrap among themselves there.
- **Add Row clears the search.** A new row has no name, which no search finds, so the search goes first. The tab sends `addDictionaryEntryAction$`, selects the new last row once its batch lands, scrolls to it once the grid has taken the new row count, a tick after the render (`onUpdated`, then `nextTick`), and focuses the grid.
- **Delete Rows is one dispatch.** It removes the rows the selection covers, among the rows the grid received, through one `removeDictionaryEntriesAction$`, which sends the removes from the end of the list back (`src/engine/AGENTS.md`, Rows leave a list from its end). The active cell then lands on the first removed row, held inside the rows left. One undo lists the rows again at the sheet's end, as a table's does (owner decisions of 2026-10-20), so a spec judges that undo by the rows and their values, not their places.
- **The row and file buttons hide on the check sheet and in a read-only document** (owner decisions of 2026-10-20). The check sheet only lists, and its checks are never exported. The search shows on all four sheets.
- **The status line counts rows.** It shows the rows the search leaves and, while the selection covers any, the rows it covers, the active cell's included and a row two ranges share counted once: as many as Delete Rows would remove.
- **An empty sheet says how to fill it.** An entry sheet that lists no row shows `dictionary.empty` over the grid with `pointer-events: none`, so a paste still reaches the grid. A read-only document shows none, since it can take neither an import nor a new row.

### CSV files

- **Import CSV opens the tab's own file input** (owner decisions of 2026-10-20): a hidden `<input type="file">` taking `.csv` beside the buttons, in every host, since the host's import callback names no CSV type and stays as it is. The file is read as bytes (`File.arrayBuffer()`), decoded (`decodeCsvBytes`) and read by its header (`readDictionaryCsv`). The input is emptied after each pick, so picking the same file again is a change too.
- **The header tells the sheet.** A file goes into the dictionary its header names whichever sheet shows, and the tab then shows that sheet and focuses its grid, so an undo by key takes the file back. The sheet keeps its search, selection and scroll, as on any switch, so a row the search hides, or one added past the rows in view, stays out of sight: the status line counts the rows the search leaves, and the toast what the file brought.
- **One file is one dispatch.** `importDictionaryAction$` folds and upserts the rows by name, so one undo takes the whole file back and the same file again sends nothing (`src/engine/AGENTS.md`, Dictionaries and derived names).
- **The toast says what came in** (Toasts in `src/components/AGENTS.md`). It is a success with `dictionary.toast.imported` as its title: the rows added, the rows updated, and the rows skipped, those with no name and those a later row of the same name replaced. While the file's terms name domains the document lacks, its second line is `dictionary.toast.unknownDomains`, how many and the first three, listed as a refusal's are. Its key names every value it shows. The counts are read before the dispatch, on the state it runs on.
- **A file no layout reads sends nothing** and opens the `dictionary.toast.unknownFormat` error toast. A read-only document takes no file and says nothing, whatever it was read as.
- **Export CSV saves the sheet shown, whole.** Every listed row in its order, whatever the search shows, in the editor's own format, a term's domain by the name of the live domain it links, so a file carries into another document and reads back to the same bytes. `exportCSV` (`src/utils/file/exportFile.ts`) names it `{databaseName}-{time}-words.csv`, `-terms.csv` or `-domains.csv`, `unnamed-` first while the database has no name, as text/csv through the host's export path.

### Keys

- **Enter on the check sheet goes to the check** of the active row and stops at the sheet (The check sheet and the marks).
- **The tab's root reads every keydown** (owner decisions of 2026-10-20). The palette (`search`), undo, redo and find (`findReplace`, which works on every tab, `src/components/explorer/AGENTS.md`) pass on to the editor's root: `DICTIONARY_PASSING_BINDINGS`. Every other press `stopsAtPanel` names, a chord of `keyBindingMap`, an arrow, Tab, Enter, Space, Home, End or a press an IME holds, stops at the tab without `preventDefault`, so the grid takes it first and no canvas binding at the root sees it.
- **An open edit keeps the palette and find.** With a grid edit open, their chords stop at the tab, prevented as the root's options prevent them, as a cell editor on the ERD tab keeps them (`src/components/explorer/AGENTS.md`, A text editor keeps the chord). Find brings the ERD tab up and the palette takes the focus, and a grid unmounted with an edit open drops it (`packages/grid/AGENTS.md`), so either would lose the text typed.
- **The tab runs undo and redo itself.** The root undoes by key on the ERD tab alone, so on this tab the keydown calls `store.undo()` or `store.redo()` and lets the press go on to the root. With a grid edit open (`GridHandle.isEditing`) or from the search field, the press stops at the tab instead, without `preventDefault`, so the open edit's or the field's own text undo takes it. The Explorer's fields hand undo to the document; this one keeps it, or an undo typed in the search would undo the document under it.
- **Copy, cut and paste stop at the tab's root,** after the grid has handled them, since the editor's root hands a copy or a paste to the diagram's clipboard (`ErdEditor.tsx`).

### The grid's theme

- **The grid takes the editor's resolved palette** (owner decisions of 2026-10-20). `toGridTheme(theme.value, previous)` builds the fifteen `GridTheme` colours from `themeContext`, so a light or dark switch, an accent or an override reaches the grid. The sheet's four surfaces come from the tab's own tokens: `dictionaryBackground` for the cells, `dictionaryHeaderBackground` for the header band, `dictionaryGridLine` for the lines between cells and `dictionaryHeaderSelect` for a header whose row or column meets the selection. They never come from a table's or a column's tokens (the package file, Give each part its own theme token). The rest come from the shared ones: `foreground` for the header labels, `active` for the cell text and a selected header's label, `focus` for the active cell's edge, `grayColor7` for the frozen border, `grayColor3` for a read-only cell, `accentColor9` for a range's edge and fill, `accentColor6` for a header whose whole row or column is selected, and the two scrollbar tokens.
- **A range is filled with the accent at 20% alpha** (`#rrggbb33`, a `#rgb` accent spelt out first), so the cells under it still read. An accent override spelt other than in hex gives `transparent`, and the range keeps its edge alone, since the fill would otherwise paint opaque over the cells.
- **The same theme comes back while every colour matches.** The grid redraws both layers on a new theme object, so the tab passes the one it handed before and gets it back until a colour changes.
- **The light steps keep the text at 4.5:1.** In light the cells are white (`override-#ffffff`), the lines `gray-8` and the band `gray-4`, since the header labels (`gray-11`) on a light `gray-5` measured 4.48:1 (2026-10-20). `dictionaryHeaderSelect` is `accent-3` under every accent: unlike `columnSelect`, it takes no `gray-6` under the gray, gold and bronze accents (`NeutralAccentThemeConfig`), since `gray-11` on a light `gray-6` measured 4.19:1 (2026-10-20).

### A read-only document

- **Every column is read-only.** `sheetColumns` marks each column read-only while the document is, so the grid opens no edit and commits no paste or clear, and the row and file buttons and the empty sheet's hint are hidden. The sheet switch, the search, the selection, the scroll, a resize and a copy still work, since none of them writes the document.
