# erd-editor

## Purpose

`@dineug/erd-editor-monorepo` is a pnpm + Vite+ workspace for an Entity-Relationship Diagram editor shipped five ways: erd-editor.io, a VSCode extension, an IntelliJ plugin, an Obsidian plugin and the `<erd-editor>` custom element on npm. The framework-free editor core is JSX compiled to the in-house `@dineug/r-html` tagged templates. Its store's actions carry a Lamport-style clock and merge through an LWW register set — the one mechanism behind collaboration, cross-tab sync and undo/redo. The same mechanism lets `@dineug/erd-editor-mcp`, a stdio MCP server also on npm, put a coding agent into a VS Code, Obsidian or JetBrains IDE editing session as one more collaborator.

## Making a Change

1. **Read `packages/<pkg>/AGENTS.md` for each package the change touches**, and for a change across a package boundary (a hub message, a bridge command, an `engine.js` or `peer.js` export) the file on each side: nothing loads a nested `AGENTS.md` on its own, and each holds rules its specs and gates enforce that this file does not repeat.
2. **Write the change with what it carries** (What a change carries, below).
3. **Run each touched package's `test` task**, which the fourteen with a `vitest.config.*` have: `pnpm exec vp run --filter ./packages/<dir> --fail-if-no-match test` builds its workspace dependencies, then runs `tsc --noEmit` and Vitest. `replication-store-worker`, `vscode-webview` and `intellij-webview` have none, and step 5's build is their check. A change to what a package hands its siblings (an export, a type, a hub or bridge message) runs `pnpm test`, since they type-check against its `dist/**/*.d.ts`.
4. **Run `pnpm --filter ./packages/<dir> --fail-if-no-match test:coverage`** where shipping source changed in a package with a `test` task: CI fails a file under 80%, and step 3 measures none.
5. **Run `pnpm check`, then `pnpm build`**, the only check of declaration emit, bundling and the three packages with no `test` task, and `pnpm peer-graph` and `pnpm size` when `erd-editor`'s output or a library it inlines changed.
6. **Run what Testing Requirements lists outside `pnpm test` that the change reaches**: the `e2e` of `erd-editor`, `app`, `r-html` or `vuerd-vscode` for behaviour a user sees there, `ERD_MCP_CONFORMANCE=required ./gradlew check` in `packages/intellij-plugin`, after step 5 built the MCP server, for a change to `intellij-plugin`, `agent-hub`, `agent-hub-host` or `mcp-server`, and the docker loop for generated SQL.
7. **Report what ran**, and name each check left to another platform or app (the Windows-only cases, the smokes) with the reason.

A step is done when its commands exit 0 on a run that exercised the change. A command that failed to start (`vp` not on `PATH`, no Chromium, `ERR_MODULE_NOT_FOUND`) has not: install with `pnpm install --frozen-lockfile` or `pnpm --filter @dineug/erd-editor exec playwright install chromium` and run it again. Neither has `vp test` in place of step 3, which skips the `tsc --noEmit` gate (`vp check` checks no types), nor a pass replayed from cache after a change that moved dependencies alone (the `tsc` bullet below). A size gate past its number (`pnpm size`, `mcp-server`'s `BUNDLE_GZIP_BUDGET`) is not done either, and its fix is the owner's: report the measured bytes and what added them, and leave the budget as it is. A change to Markdown alone needs no check, except in three files a build reads: `schema-sql-parser`'s `src/schema_sql_test_case.md`, its spec's fixture, and `intellij-plugin`'s `README.md` and `CHANGELOG.md`, which `./gradlew buildPlugin` turns into the plugin's description and change notes.

## For AI Agents

### Working In This Directory

- **pnpm only.** Cross-package deps are `workspace:*`; import a sibling by package name, never through a relative path into its `src/`.
- **Command surface split.** A name lives in `run.tasks` or in package.json `scripts`, never both.

  | Target | Invocation |
  | --- | --- |
  | task (`build`, `test`) | `pnpm exec vp run --filter <pkg> --fail-if-no-match <task>`, or `pnpm exec vp run -r <task>` |
  | script (`dev`, `e2e`, `typecheck`, `test:coverage`) | `pnpm --filter <pkg> <script>` |
  | Gradle (`intellij-plugin`) | `cd packages/intellij-plugin && ./gradlew <task>` |

  `<pkg>` is an npm name (`@dineug/erd-editor-mcp`) or a folder as `./packages/mcp-server`; the bare folder names this file uses are not npm names, and a filter matching nothing runs nothing and exits 0 unless `--fail-if-no-match` is given. `vp` is the workspace's `node_modules/.bin/vp`, which package scripts and the git hooks put on `PATH` and a shell without a global Vite+ does not, so a bare `vp …` typed there fails to start. Flags go before the task: `vp run build -r` forwards `-r` to the task. `vp build` / `vp test` are built-ins that skip `run.tasks`, the `tsc --noEmit` gate and `dependsOn`. There is no `vite` binary.
- **Read the installed toolchain, not the one you remember**: Vite+ 1.0, Vitest 5, TypeScript 7 and effect 4.0.0 are newer than most training data and moved their APIs (effect 4.0.0 has no `Effect.catchAll` or `Context.Tag`; this repository writes `Effect.catch` and `Context.Service`). Read what `pnpm install` put on disk: `node_modules/vite-plus/docs/`, and effect's `AGENTS.md`, `ai-docs/` and `src/` (`packages/agent-hub/node_modules/effect/`). Where a bundled guide disagrees with this file, this file holds: vite-plus's checklist takes `vp check` and `vp test` for type checks, and here neither is one.
- **TypeScript 7.0.2's native `tsc` is invisible to Vite Task**, its reads and its writes alike, so every task declares `cache.input`. Library packages derive it in `package-metadata.ts` and `check-task-inputs.mjs` recomputes it; app tasks list their own, and the check only matches their sibling `dist/**/*.d.ts` globs to declared dependencies. Neither names `pnpm-lock.yaml` or `pnpm-workspace.yaml`, and a `catalog:` bump changes no `package.json`, so after a change that moves dependencies alone a `tsc --noEmit` gate can replay its cached pass over new type errors: run `pnpm cache:clear` first. CI's cold cache never meets this. Without `cache.output` a cache hit restores the files the traced commands wrote, never one `tsc` wrote; `output: []` restores nothing. `@typescript/typescript6` serves `vite-plugin-dts` and the compiler API three `erd-editor` specs use: `coordinateAuthority.test.ts` and `sceneSvg.attributes.test.ts` parse sources with it, and `jsonShape.test.ts` reads identifiers with its scanner.
- **Library builds.** Nine private libraries (`r-html`, `vite-plugin-r-html`, `schema-sql-parser`, `uuid`, `erd-editor-schema`, `webview-bridge`, `webview-client`, `agent-hub`, `agent-hub-host`) build `minify: false` + `preserveModules: true` with `sideEffects: false`, so the consumer prunes per file and minifies once; `agent-hub-host` alone adds `node: true`, since it imports node builtins, which a browser build resolves to an empty stub with only a warning. `erd-editor` keeps chunks and no `sideEffects` field (its `AGENTS.md` says why).
- **Externals decide what ships.** `createExternal` keeps `dependencies` + `peerDependencies` as bare imports and inlines the rest. `erd-editor` lists the private libraries as devDependencies so they inline; moving one into `dependencies` ships an import of a package not on npm. Two private libraries have peers: `agent-hub` names `effect`, `agent-hub-host` names `effect` and `@effect/platform-node`, and `agent-hub-host` names `agent-hub` in `dependencies`, as `erd-editor-schema` names `uuid`, which `erd-editor` and `mcp-server` list as a devDependency and inline. Their `dist/*.js` and `.d.ts` keep those imports bare, and each consumer (`mcp-server`, `vuerd-vscode`, `obsidian-plugin`) lists them as devDependencies, effect's from the same `catalog:` pin, and inlines the one copy it resolves (`ssr.noExternal: true` in the Node bundles), shared with its own effect code; two copies of `agent-hub` would make two `HubRequestError` classes, and every refusal would answer `internal`. A consumer program that type-checks those `.d.ts` files needs `skipLibCheck`, which `tsconfig.app.json` and the extension's `tsconfig.json` set: effect's own declarations name types lib ES2022 lacks (`TextDecoderOptions`); `agent-hub-host`'s also need `@types/node`.
- **Workers.** `erd-editor`'s three SharedWorkers and the replica Worker ship as `dist/workers/*.js`, spawned from `new URL('./workers/x.js', import.meta.url)` — the spelling `worker-url.ts` writes, which webpack, Rspack and Vite all bundle from a dependency. `vscode-webview` rebuilds them as same-origin blobs (`same-origin-worker.ts`), `intellij-webview` loads them by URL, the UMD build and `obsidian-plugin` inline them (`inline-worker.ts`).
- **A cache replay does not empty a task's `cache.output` directory**, and an explicit one archives whatever its glob matches as each of the task's commands ends, the `tsc --noEmit` gate too, so a tree that has seen several builds holds stale chunks beside live ones. `pnpm cache:clear` and rebuild before packaging or publishing.
- **`@/*` → `<package>/src/*`** in every TS package's `tsconfig.json`, mirrored by a Vite alias in the factory and in each Vitest config — a new config needs it too.
- **Formatting is TypeScript only**: `fmt.ignorePatterns` lists every other extension, because oxfmt does not re-include after a global exclude; that spelling formats nothing and still passes. oxlint ignores `.gitignore`; its ignore list is in `vite.config.ts`, so `pnpm check` lints a stray file that list misses, as Vitest runs any `src/**/*.test.ts`: keep scratch scripts and notes outside the repository.
- **Lint scope.** The rule overrides, import sort included, cover `**/src/**/*.{ts,tsx}`; the comment rules are global. Type-aware lint is off. Most `typescript/*` strictness rules are off on purpose, and so are the twelve React Compiler rules oxlint 1.85 put in `correctness` (`react/purity`, `react/refs`, …): they misread `erd-editor`'s r-html hooks, and `app` runs no React Compiler. Leave both off in unrelated changes.
- **Comments are lint-enforced** (`tools/eslint-rules/`); what no longer fits goes to an `AGENTS.md` or a test. A rule states its reason itself, never a label from a plan outside the tree (the gitignored `.omc/`: `X9`, `D19`), which no reader can follow; the `AC-*` tags in test titles stay. A measured figure keeps its current value, date and reason, never a chain of earlier values, which git history holds.

  | Rule | Bound |
  | --- | --- |
  | `local/jsdoc-prose-limit` | One prose paragraph, three lines; `@example` / `@tag` lines do not count |
  | `local/comment-run-limit` | Three consecutive line comments that open their line; a bare `//` counts |
  | `local/jsdoc-attached` | A JSDoc block sits on a declaration — not an import, re-export or another block; a tags-only block may sit on an import or re-export |
  | `local/no-comment-markdown` | No emphasis, backticks, fences, tables or lists in comment prose; `@example` exempt |

  `no-comment-markdown --fix` mis-pairs spans containing backticks or `${…}`; review those hunks. `.github/` YAML keeps the bounds by hand.
- **What a change carries**: its specs, enough to keep each touched file at 80%, and every `AGENTS.md` line it makes false. A version, a CHANGELOG entry, a new size budget (`pnpm size`'s or `mcp-server`'s `BUNDLE_GZIP_BUDGET`) and a fix outside the change wait for the owner; name the one that looks due in the report. Every published version stays as `main` has it (the `version` of `@dineug/erd-editor`, `@dineug/erd-editor-mcp` and `vuerd-vscode`, the Obsidian `manifest.json` and `versions.json`, IntelliJ's `pluginVersion`), and IntelliJ's `## [Unreleased]` heading stays empty, since the release procedure writes the versions and the CHANGELOGs, and a version raised on a branch ships a number no release made. No doc, comment, test title or constant names a released version, or every release would have to edit it: describe the behaviour, and read a version from its manifest (`mcp-server`'s `server.ts` imports its `package.json`). Document-schema, host, toolchain and dependency versions are exempt.
- **Ask the owner before a step that leaves this machine or cannot be taken back**, unless the task asked for it: a publish (`npm publish`, `publish:vsce`, `./gradlew publishPlugin`), a push, tag or release here or in `dineug/erd-editor-obsidian-plugin`, a PR or issue comment, a change to what Contracts Outside This Repo lists. A maintainer's machine can hold the credentials, and a registry refuses a version it has published. Commit through the hooks and fix what they report (`--no-verify`, `VP_GIT_HOOKS=0` and `HUSKY=0` skip them). In `~/.erd-editor/ide` remove only the files of a process you started; the rest are the owner's open editor windows.
- **Commits**: Conventional Commits via commitlint, `subject-case` off (subjects are capitalized), header and body lines ≤ 100 chars. The hooks live in the generated `.vite-hooks/_/`, which `pnpm install` writes and which puts `node_modules/.bin` on `PATH`, so a fresh clone or worktree runs no hook before its install. `vp staged` hides a partly staged file's unstaged hunks while it runs, so commit such a file only while nothing else edits it.
- **Pull requests.** `main` has no branch protection, so before a merge watch every check of both workflows finish (`gh pr checks <n> --watch`). `Closes #N` closes no GitHub Discussion, where many requests live: name it in the body, and tell the owner after the merge that it is still open.

### Testing Requirements

- `pnpm test` = `vp run -r test` over the fourteen packages with a `vitest.config.*` (a library's `test` task exists because of that file), each `tsc --noEmit` then Vitest, imported as `vite-plus/test`.
- Vitest collects `src/**/*.test.ts` only (`erd-editor`: `.test.{ts,tsx}`); a spec named or placed otherwise never runs. `erd-editor`'s `browser` project (`*.browser.test.{ts,tsx}`, real Chromium) makes `pnpm test` need `pnpm --filter @dineug/erd-editor exec playwright install chromium`.
- v8 coverage at `perFile` 80% on all four metrics gates `test:coverage`, and `pnpm test` measures none. CI runs `pnpm -r --no-bail test:coverage`, so a file under 80% in any of the fourteen packages fails it; each package's `coverage.include` names what it measures (`obsidian-plugin`'s leaves out what runs only inside Obsidian, under the smoke). Cover a gap with a test; the one hint in `src/` is `/* v8 ignore next -- @preserve */` on `erd-editor`'s `if (import.meta.hot)` blocks.
- **A failing spec is fixed at its cause.** CI retries `erd-editor`'s browser specs and the Playwright suites twice and a local run never does, so a local failure is real until shown otherwise. Fix the race, wall-clock wait or repeated work rather than add a timeout, a retry or a skip; show a spec written for a fix failing on the code before it; report a spec that looks wrong, with its output.
- **The hub packages' specs pass on Windows too**: CI's `hub-windows` runs the `test` task of `agent-hub`, `agent-hub-host`, `mcp-server`, `vuerd-vscode` and `obsidian-plugin` on `windows-latest`.
  - **A listener goes through `specPipePath`** (`src/__test-utils__/platform.ts` in `agent-hub-host` and `mcp-server`; `obsidian-plugin`'s `servePeer` and `mcp-server`'s `bin.test.ts` inline it), a named pipe on Windows, where Node listens on nothing else; never stat a live pipe, which connects to it as a peer.
  - **A case that cannot exist on one platform** is gated with `it.runIf` or `it.skipIf` on `process.platform`, a comment beside it giving the reason, and the other platform gets its own form of the check where the product has one (`nodeHub.test.ts`'s errno case). Every gated case so far is `mcp-server`'s, and its `AGENTS.md` names each, but one: `erd-editor`'s `src/i18n/messages/fit.browser.test.ts`, a browser spec gated on `server.platform` (the Vitest server's `process.platform`), since its widths hold in the font a Mac resolves the stack to, as `erd-editor`'s `AGENTS.md` (Dictionaries) says.
  - **Coverage is measured on Linux only**, so every win32 branch in shipping code must stay reachable from a memory spec that passes `win32`.
  - **Locally the symlink specs need Developer Mode or an elevated shell**; the hosted runner is an administrator.
- **The gates want LF files**, which `.gitattributes` gives every checkout whatever `core.autocrlf` says: on the CRLF files Git for Windows writes by default, `vp check` flags every file and two specs that read committed bytes fail (`erd-editor`'s `moduleLayout.test.ts`, `app`'s `server/auth/imports.test.ts`), while the hub packages' specs pass either way. A clone made before `.gitattributes` keeps its CRLF files until Git writes them again.
- `pnpm check` = `vp check` (oxfmt + oxlint) + root `tsc --noEmit` + `node --test tools/vite-config.test.ts` + `check-task-inputs.mjs`.
- `pnpm size`, after `pnpm build`: gzip of every script reachable from `erd-editor`'s `exports` vs `packages/erd-editor/.size-baseline.json`. `budgetGzip` is a regression watch whose number the owner sets: a change past it reports the measured bytes and what added them, and the budget is re-pinned (`--set-budget --budget-gzip <bytes> --budget-note <why>`) only once the owner accepts a number. No `AGENTS.md` or README records the measured figure, which every change to the bundle moves and two branches then conflict on: `pnpm size` prints it (the owner's call on 2026-10-10).
- `pnpm peer-graph`, after `pnpm build`: the scripts `erd-editor`'s `peer.js` reaches must hold no `SharedWorker`, `customElements`, `document.`, `window.` or `navigator.` and import only `es-toolkit` (and `/compat`), `graphql`, `rxjs`. `erd-editor`'s `src/peer/imports.test.ts` holds the sources to the same two rules in `pnpm test`; change both allowlists together.
- `pnpm --filter <pkg> e2e`, outside `pnpm test`: Playwright for `@dineug/erd-editor`, `@dineug/erd-editor-app`, `@dineug/r-html`; `@vscode/test-cli` for `vuerd-vscode` (`xvfb-run -a` on Linux). Each runs in its own CI job.
- The two editor smokes, outside `pnpm test` and CI, drive the built plugin in the real editor and its hub with the built MCP server, so build `@dineug/erd-editor-mcp` first: `pnpm --filter @dineug/erd-editor-obsidian-plugin smoke` (macOS or Windows) and `pnpm --filter @dineug/erd-editor-intellij-plugin smoke` (macOS, after `./gradlew buildWebview`). Each writes a real lock and socket under `~/.erd-editor/ide` and deletes only its own pid's; its package's `AGENTS.md` (Testing Requirements) gives the steps and knobs.

Stop it by its pid or over CDP, never by app name (`pkill -x Obsidian`), which closes the person's own windows too.

- **Windows check of the IntelliJ hub**: follow `packages/intellij-plugin/AGENTS.md` § Windows Verification (named-pipe hub), step by step.
- SQL-generation changes: `docker/<vendor>/` plus `data/*.sql` is the manual loop.
- CI `ci.yml`: `check` (`pnpm check`, then builds `app`'s and `vuerd-vscode`'s dependencies for their `typecheck` scripts, which read siblings' `dist/**/*.d.ts`, then `app`'s `e2e:typecheck`), `ci` (`pnpm test`, every package's `test:coverage`, `pnpm build`, `pnpm peer-graph`, `pnpm size`), `e2e`, `app-e2e`, `r-html-e2e`, `vscode-extension-e2e`, `hub-windows` (the five hub packages' `test` task on `windows-latest`, which builds their workspace dependencies, the `erd-editor` chain included; no coverage there).

Its `build`, `test-windows` and `verify` jobs are in `packages/intellij-plugin/AGENTS.md` (Testing Requirements); `test-windows` is the one CI job where the Kotlin named-pipe hub runs.

### Common Patterns

- **`erd-editor` is authored in JSX** that `rHtml()` compiles to r-html templates (or, under `/** @jsxHost konva */`, to the Konva scene host); `r-html` itself stays tagged-template. See `packages/erd-editor` and `packages/vite-plugin-r-html`.
- Named exports; a component module default-exports its component. Import and export order is `simple-import-sort`'s, applied by `vp check --fix` (the pre-commit hook runs it on staged files), so leave the order to it.
- A barrel `index.ts` per feature directory; `src/index.ts` is a package's public surface.
- **The product is ERD Editor** in every sentence a person or an agent reads, in every distribution (the owner's call on 2026-09-25): store listings, the VS Code `displayName`, the IntelliJ `<name>`, the Obsidian manifest `name`, erd-editor.io's pages, the MCP server's prose, the console app names. Google's brand review matches the consent screen's name to the home page. Identifiers keep `erd-editor` (packages, `<erd-editor>`, files, setting ids, keys, routes), and a sentence that means the site writes erd-editor.io; `packages/app/AGENTS.md` lists the app's own.
- **A user-visible change reaches every README that describes it**: the root one and those of `erd-editor` (npm), `vscode-extension`, `intellij-plugin` (between its `Plugin description` markers) and `obsidian-plugin`, the last three store listings; the Obsidian one reaches the directory only once copied to the release repository's root. A new distribution or listing link also goes into the READMEs of `mcp-server` and `app`. docs.erd-editor.io is another repository, updated once the change is on `main`.
